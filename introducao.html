O que é TypeScript

O TypeScript é o JavaScript com tipos. Você escreve quase o mesmo código de sempre, mas pode dizer “isto aqui é um número”, “esta função recebe um texto”. Um programa chamado compilador (o tsc) confere tudo e depois gera o JavaScript que o navegador ou o Node vão rodar.

Você vai aprender
  • O problema que o TypeScript resolve, com um erro real do JavaScript.
  • O caminho do código: arquivo .ts → tsc → arquivo .js → node.
  • Que os tipos somem no JavaScript gerado.
  • Como ler a primeira mensagem do compilador.

A ideia: um revisor antes da gráfica

Imagine que você escreveu um livro. Antes de mandar para a gráfica, um revisor lê tudo e marca os erros. O JavaScript vai direto para a gráfica: os erros aparecem só quando o leitor (o usuário) abre o livro. O TypeScript coloca um revisor no meio. Ele não muda a história, só aponta o que não faz sentido.

1. Um erro que o JavaScript deixa passar

Veja esta função em JavaScript puro, num arquivo soma.js. Ela deveria somar dois números:

function soma(a, b) {
  return a + b;
}

console.log(soma(2, 3));
console.log(soma("2", 3));
$ node soma.js
5
23

O segundo resultado é 23, e não 5. Com um texto no meio, o + do JavaScript junta em vez de somar. Nenhum aviso: o programa rodou feliz, com o resultado errado.

2. O mesmo código em TypeScript

Agora a mesma função num arquivo .ts, dizendo que a e b são do tipo number:

function soma(a: number, b: number) {
  return a + b;
}

console.log(soma(2, 3));
console.log(soma("2", 3));

Antes de rodar, pedimos ao compilador para conferir e gerar o JavaScript:

$ npx tsc
src/soma.ts(6,18): error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.

O revisor achou o problema na linha 6, coluna 18: “um argumento do tipo string não pode ser passado para um parâmetro do tipo number”. O erro apareceu antes de qualquer usuário ver um 23 na tela.

Mensagens em inglês

O tsc escreve em inglês, e este guia mostra as mensagens exatamente como elas aparecem. Logo depois de cada uma, vem a explicação em português. Com o tempo você reconhece as mais comuns só pelo número, como o TS2345.

3. Os tipos somem no JavaScript

Corrigindo a chamada, o tsc gera o arquivo dist/soma.js:

function soma(a: number, b: number) {
  return a + b;
}

console.log(soma(2, 3));
console.log(soma(10, 20));
$ npx tsc
$ node dist/soma.js
5
30
function soma(a, b) {
    return a + b;
}
console.log(soma(2, 3));
console.log(soma(10, 20));
export {};
//# sourceMappingURL=soma.js.map

Repare: o : number sumiu. O JavaScript gerado é praticamente o que você escreveria à mão. As duas linhas do fim vêm das configurações do projeto: o export {}; marca o arquivo como um módulo (aula Módulos) e o comentário sourceMappingURL aponta para um “mapa” que liga o .js de volta ao .ts, útil para depurar. Os tipos servem só para conferir; o Node nunca os vê.

O caminho do código

  1. Você escreve src/soma.ts, com tipos.
  2. O npx tsc confere os tipos e mostra os erros, se houver.
  3. O tsc escreve dist/soma.js, sem os tipos.
  4. O node dist/soma.js roda o JavaScript.

Resumo

  • TypeScript é JavaScript com tipos; o compilador tsc confere e gera o .js.
  • Erros de tipo aparecem ao compilar, antes de o programa rodar.
  • Os tipos somem no JavaScript gerado.
  • Caminho do guia: src/arquivo.ts → npx tsc → node dist/arquivo.js.
