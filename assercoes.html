Asserções de Tipo (as e !)

Às vezes você sabe mais do que o compilador: “confie em mim, isto é um número”. Uma asserção diz exatamente isso. Ela não muda o valor nem confere nada quando o programa roda: só muda o que o compilador acha. Por isso é uma ferramenta útil e perigosa.

Você vai aprender
  • O operador as.
  • O ! (non-null assertion), que apaga o undefined.
  • O as const.
  • Os limites: quando o compilador recusa a asserção, e o erro que uma asserção errada esconde.

1. as

const dados: unknown = JSON.parse('{"nome": "Ana", "idade": 30}');

type Pessoa = { nome: string; idade: number };
const p = dados as Pessoa;
console.log(p.nome.toUpperCase(), p.idade + 1);
$ npx tsc && node dist/as.js
ANA 31

O JSON.parse devolve algo sem tipo conhecido. Com as Pessoa, você assume a responsabilidade de dizer o que veio. Se estiver certo, ótimo.

3. O compilador recusa asserções absurdas

const texto = "123";
const n = texto as number;
$ npx tsc
src/as-absurdo.ts(2,11): error TS2352: Conversion of type 'string' to type 'number' may be a mistake because neither type sufficiently overlaps with the other. If this was intentional, convert the expression to 'unknown' first.

De string para number não dá: os tipos não têm nada em comum. A mensagem até sugere a saída de emergência: converter primeiro para unknown, a asserção dupla texto as unknown as number, que quase sempre indica um problema no desenho do código. Para converter de verdade, use Number(texto).

4. O ! (non-null assertion)

O ! depois de um valor diz: “isto não é null nem undefined”.

const notas = new Map<string, number>([["Ana", 9]]);

const nota1 = notas.get("Ana");
console.log(nota1.toFixed(1));
$ npx tsc
src/exclamacao.ts(4,13): error TS18048: 'nota1' is possibly 'undefined'.
const notas = new Map<string, number>([["Ana", 9]]);

const nota1 = notas.get("Ana")!;
console.log(nota1.toFixed(1));

const nota2 = notas.get("Duda")!;
console.log(nota2.toFixed(1));
$ npx tsc && node dist/exclamacao.js
9.0
file:///home/ana/projeto/dist/exclamacao.js:5
console.log(nota2.toFixed(1));
                  ^

TypeError: Cannot read properties of undefined (reading 'toFixed')
    at file:///home/ana/projeto/dist/exclamacao.js:5:19
    at ModuleJob.run (node:internal/modules/esm/module_job:561:25)
    at async node:internal/modules/esm/loader:647:26
    at async asyncRunEntryPointWithESMLoader (node:internal/modules/run_main:101:5)

Para a Ana deu certo. Para a Duda, que não está no mapa, o ! mentiu e o programa quebrou. Prefira ?., ?? ou um if; deixe o ! para quando você tem certeza absoluta.

5. as const

O as const é uma asserção segura: ele só deixa o tipo mais estreito, com valores literais e somente leitura.

const cores = ["vermelho", "verde"];
const coresFixas = ["vermelho", "verde"] as const;

const t1: null = cores;
const t2: null = coresFixas;
$ npx tsc
src/as-const.ts(4,7): error TS2322: Type 'string[]' is not assignable to type 'null'.
src/as-const.ts(5,7): error TS2322: Type 'readonly ["vermelho", "verde"]' is not assignable to type 'null'.

Sem as const, é um string[] qualquer. Com ele, é uma tupla somente leitura com os dois textos exatos.

Quando dá errado

A sintaxe antiga com <Tipo>

Em código antigo você pode ver <Pessoa>dados no lugar de dados as Pessoa. As duas formas são equivalentes nos arquivos .ts, mas a com < > não funciona em arquivos .tsx (React). Use sempre as.

Missões

Missão: use as Produto para dizer o tipo do resultado do JSON.parse e mostre Caneca custa R$ 35.

type Produto = { nome: string; preco: number };
const p = JSON.parse('{"nome": "Caneca", "preco": 35}');

type Produto = { nome: string; preco: number };
const p = JSON.parse('{"nome": "Caneca", "preco": 35}') as Produto;
console.log(`${p.nome} custa R$ ${p.preco}`);

Caneca custa R$ 35

Missão: tente a asserção absurda const n = "42" as number; e cole o erro TS2352.

const n = Number("42");
console.log(n);

const n = "42" as number;
console.log(n);

src/missao.ts(1,11): error TS2352: Conversion of type 'string' to type 'number' may be a mistake because neither type sufficiently overlaps with the other. If this was intentional, convert the expression to 'unknown' first.

Resumo

  • as T muda o que o compilador acha, não o valor; uma asserção errada vira erro rodando.
  • O compilador recusa asserções entre tipos sem nada em comum (TS2352).
  • ! apaga null/undefined: use pouco.
  • as const é seguro: literais e somente leitura.
