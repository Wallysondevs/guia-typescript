Herança e implements

Classes podem herdar de outras (extends): a filha ganha tudo da mãe e acrescenta ou troca o que quiser. E uma classe pode prometer seguir uma interface (implements): o compilador confere se a promessa foi cumprida.

Você vai aprender
  • extends e super.
  • override e o protected na prática.
  • Classes e métodos abstract.
  • implements: classes que seguem uma interface.

1. extends e super

class Animal {
  constructor(protected nome: string) {}

  apresentar(): string {
    return `Eu sou ${this.nome}`;
  }
}

class Cachorro extends Animal {
  constructor(nome: string, private raca: string) {
    super(nome);
  }

  override apresentar(): string {
    return super.apresentar() + `, um ${this.raca}`;
  }

  latir(): string {
    return `${this.nome}: Au au!`;
  }
}

const rex = new Cachorro("Rex", "vira-lata");
console.log(rex.apresentar());
console.log(rex.latir());

const bicho: Animal = rex;
console.log(bicho.apresentar());
$ npx tsc && node dist/heranca.js
Eu sou Rex, um vira-lata
Rex: Au au!
Eu sou Rex, um vira-lata
  • super(nome) chama o construtor da mãe; é obrigatório antes de usar this.
  • override marca que o método substitui um da mãe; super.apresentar() chama a versão original.
  • protected nome é visível na filha (this.nome em latir), mas não fora.
  • Um Cachorro pode ser guardado numa variável Animal, e chamar apresentar() usa a versão do cachorro.

2. Esquecer o super

class Animal {
  constructor(protected nome: string) {}
}
class Gato extends Animal {
  constructor(nome: string) {
    console.log("criando gato");
  }
}
$ npx tsc
src/sem-super.ts(5,3): error TS2377: Constructors for derived classes must contain a 'super' call.

3. Classes abstratas

Uma classe abstract é um molde incompleto: não se cria objeto dela, só das filhas. Um método abstract não tem corpo, e toda filha é obrigada a escrevê-lo:

abstract class Forma {
  abstract area(): number;

  descrever(): string {
    return `${this.constructor.name} com área ${this.area().toFixed(2)}`;
  }
}

class Circulo extends Forma {
  constructor(private raio: number) {
    super();
  }
  area(): number {
    return Math.PI * this.raio ** 2;
  }
}

class Quadrado extends Forma {
  constructor(private lado: number) {
    super();
  }
  area(): number {
    return this.lado ** 2;
  }
}

const formas: Forma[] = [new Circulo(1), new Quadrado(3)];
for (const f of formas) console.log(f.descrever());
$ npx tsc && node dist/abstrata.js
Circulo com área 3.14
Quadrado com área 9.00

E as duas regras da classe abstrata, quebradas de propósito:

abstract class Forma {
  abstract area(): number;
}
const f = new Forma();

class Triangulo extends Forma {}
$ npx tsc
src/abstrata-erro.ts(4,11): error TS2511: Cannot create an instance of an abstract class.
src/abstrata-erro.ts(6,7): error TS2515: Non-abstract class 'Triangulo' does not implement inherited abstract member area from class 'Forma'.

4. implements

Uma interface pode servir de contrato para uma classe. Com implements, o compilador confere se a classe tem tudo o que a interface pede:

interface Imprimivel {
  imprimir(): string;
}
interface Salvavel {
  salvar(): boolean;
}

class Relatorio implements Imprimivel, Salvavel {
  constructor(private titulo: string) {}
  imprimir(): string {
    return "== " + this.titulo + " ==";
  }
  salvar(): boolean {
    return true;
  }
}

const docs: Imprimivel[] = [new Relatorio("Vendas"), { imprimir: () => "nota solta" }];
for (const d of docs) console.log(d.imprimir());
$ npx tsc && node dist/implements.js
== Vendas ==
nota solta

Uma classe herda de uma só classe, mas pode implementar várias interfaces. E repare que o objeto solto { imprimir: … } também serve como Imprimivel: a tipagem é estrutural.

Quando dá errado

Prometer e não cumprir 
interface Imprimivel {
  imprimir(): string;
}
class Foto implements Imprimivel {
  mostrar() {
    return "foto";
  }
}
$ npx tsc
src/promessa.ts(4,7): error TS2420: Class 'Foto' incorrectly implements interface 'Imprimivel'.
  Property 'imprimir' is missing in type 'Foto' but required in type 'Imprimivel'.
override sem método na mãe 
class Animal {
  falar() { return "..."; }
}
class Pato extends Animal {
  override grasnar() { return "quack"; }
}
$ npx tsc
src/override.ts(5,12): error TS4113: This member cannot have an 'override' modifier because it is not declared in the base class 'Animal'.

O override protege contra erros de digitação: se a mãe não tem o método, o compilador avisa.

Missões

Missão: crie class Moto extends Veiculo, cujo construtor recebe só a marca e chama super(marca, 2). Mostre new Moto("Honda").descrever().

class Veiculo {
  constructor(protected marca: string, protected rodas: number) {}
  descrever(): string {
    return `${this.marca}: ${this.rodas} rodas`;
  }
}

class Veiculo {
  constructor(protected marca: string, protected rodas: number) {}
  descrever(): string {
    return `${this.marca}: ${this.rodas} rodas`;
  }
}
class Moto extends Veiculo {
  constructor(marca: string) {
    super(marca, 2);
  }
}
console.log(new Moto("Honda").descrever());

Honda: 2 rodas

Missão: faça a classe Pix implementar a interface Pagamento e mostre new Pix().pagar(50), que devolve Pix de R$ 50 enviado.

interface Pagamento {
  pagar(valor: number): string;
}
class Pix {
}

interface Pagamento {
  pagar(valor: number): string;
}
class Pix implements Pagamento {
  pagar(valor: number): string {
    return `Pix de R$ ${valor} enviado`;
  }
}
console.log(new Pix().pagar(50));

Pix de R$ 50 enviado

Resumo

  • extends herda; super(…) chama o construtor da mãe; override marca a substituição.
  • protected é visível na classe e nas filhas.
  • abstract: molde incompleto, sem new; métodos abstratos obrigam as filhas.
  • implements confere se a classe cumpre uma ou várias interfaces.
