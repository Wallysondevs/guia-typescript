O operador satisfies

Anotar uma variável (const x: Tipo = …) confere o valor, mas faz a variável “esquecer” os detalhes e ficar só com o Tipo. Não anotar guarda os detalhes, mas não confere nada. O satisfies faz as duas coisas: confere o valor e mantém o tipo exato que o TypeScript inferiu.

Você vai aprender
  • A diferença entre anotar e usar satisfies.
  • Por que satisfies é mais seguro que as.
  • Combinar com Record e as const.

1. Anotação apaga detalhes

type Cores = Record<string, string | number[]>;

const paleta: Cores = {
  primaria: "#3366ff",
  fundo: [255, 255, 255],
};

console.log(paleta.primaria.toUpperCase());
console.log(paleta.fundo.map((c) => c / 255));
$ npx tsc
src/anotacao.ts(8,13): error TS18048: 'paleta.primaria' is possibly 'undefined'.
src/anotacao.ts(8,29): error TS2339: Property 'toUpperCase' does not exist on type 'string | number[]'.
  Property 'toUpperCase' does not exist on type 'number[]'.
src/anotacao.ts(9,13): error TS18048: 'paleta.fundo' is possibly 'undefined'.
src/anotacao.ts(9,26): error TS2339: Property 'map' does not exist on type 'string | number[]'.
  Property 'map' does not exist on type 'string'.
src/anotacao.ts(9,31): error TS7006: Parameter 'c' implicitly has an 'any' type.

Com a anotação : Cores, cada campo virou string | number[] (e o noUncheckedIndexedAccess ainda soma undefined, porque o Record<string, …> aceita qualquer chave). O TypeScript esqueceu que primaria é texto e fundo é lista.

2. satisfies confere e mantém

type Cores = Record<string, string | number[]>;

const paleta = {
  primaria: "#3366ff",
  fundo: [255, 255, 255],
} satisfies Cores;

console.log(paleta.primaria.toUpperCase());
console.log(paleta.fundo.map((c) => c / 255));
$ npx tsc && node dist/satisfies.js
#3366FF
[ 1, 1, 1 ]

O objeto foi conferido contra Cores, mas paleta.primaria continua string e paleta.fundo continua number[]. E erros continuam sendo pegos:

type Cores = Record<string, string | number[]>;

const paleta = {
  primaria: "#3366ff",
  borda: true,
} satisfies Cores;

console.log(paleta.sombra);
$ npx tsc
src/satisfies-erro.ts(5,3): error TS2322: Type 'boolean' is not assignable to type 'string | number[]'.
src/satisfies-erro.ts(8,20): error TS2339: Property 'sombra' does not exist on type '{ primaria: string; borda: boolean; }'.

Dois ganhos: o valor errado (true) foi recusado, e acessar uma chave que não existe (sombra) também, porque o tipo da variável é o objeto exato.

3. satisfies x as

O as manda o compilador acreditar; o satisfies pede para conferir:

type Usuario = { nome: string; idade: number };

const a = { nome: "Ana" } as Usuario;
const b = { nome: "Caio" } satisfies Usuario;
console.log(a, b);
$ npx tsc
src/as.ts(4,28): error TS2741: Property 'idade' is missing in type '{ nome: string; }' but required in type 'Usuario'.

O as deixou passar um usuário sem idade. O satisfies pegou.

4. Com as const: chaves e valores exatos

type Rotas = Record<string, `/${string}`>;

const rotas = {
  inicio: "/",
  perfil: "/perfil",
  ajuda: "/ajuda",
} as const satisfies Rotas;

type NomeRota = keyof typeof rotas;
const ir: NomeRota = "perfil";
console.log(ir, "->", rotas[ir]);

const errada: NomeRota = "contato";
$ npx tsc
src/as-const.ts(13,7): error TS2322: Type '"contato"' is not assignable to type '"ajuda" | "inicio" | "perfil"'.

as const satisfies Rotas: os valores são conferidos (todo caminho começa com /) e as chaves exatas viram um tipo útil (NomeRota).

Quando dá errado

Propriedade a mais 
type Config = { porta: number; host: string };

const cfg = {
  porta: 8080,
  host: "localhost",
  debug: true,
} satisfies Config;
$ npx tsc
src/a-mais.ts(6,3): error TS2353: Object literal may only specify known properties, and 'debug' does not exist in type 'Config'.

Como na anotação, um objeto escrito na hora não pode ter campos que o tipo desconhece. Adicione debug ao tipo ou remova do objeto.

Exercícios

1. A palavra

Complete para conferir o objeto contra Config sem perder o tipo exato:

const cfg = { porta: 80 } Config;

2. Ordem

Complete na ordem certa:

const rotas = { … } as satisfies Rotas;

3. Qual não confere?

Qual das três formas (anotação, satisfies, as) praticamente não confere o valor? Escreva a palavra-chave.

4. Com const p = { cor: "azul" } satisfies Record<string, string>, qual é o tipo de p.cor?

5. { nome: "Caio" } satisfies { nome: string; idade: number }…

Missões

Missão: troque a anotação : Precos por satisfies Precos para o código compilar. Saída esperada: CAFÉ 6.50.

type Precos = Record<string, string | number>;
const cardapio: Precos = {
  nome: "café",
  valor: 6.5,
};
console.log(cardapio.nome.toUpperCase(), cardapio.valor.toFixed(2));

type Precos = Record<string, string | number>;
const cardapio = {
  nome: "café",
  valor: 6.5,
} satisfies Precos;
console.log(cardapio.nome.toUpperCase(), cardapio.valor.toFixed(2));

CAFÉ 6.50

Missão: o as está escondendo um campo faltando. Troque por satisfies Produto, leia o erro e complete o objeto com estoque: 40. Saída esperada: Caneta: 40 em estoque.

type Produto = { nome: string; estoque: number };
const p = { nome: "Caneta" } as Produto;
console.log(`${p.nome}: ${p.estoque} em estoque`);

type Produto = { nome: string; estoque: number };
const p = { nome: "Caneta", estoque: 40 } satisfies Produto;
console.log(`${p.nome}: ${p.estoque} em estoque`);

Caneta: 40 em estoque

Resumo

  • satisfies confere o valor e mantém o tipo exato inferido.
  • Anotação confere, mas generaliza; as quase não confere.
  • as const satisfies T dá valores exatos conferidos.
