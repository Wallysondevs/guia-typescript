Módulos (import e export)

Programa de verdade não cabe num arquivo só. Com módulos, cada arquivo guarda uma parte e exporta o que os outros podem usar; quem precisa importa. O TypeScript confere os tipos entre os arquivos, e o nosso projeto (com "type": "module" e module: nodenext) usa os módulos modernos do JavaScript.

Você vai aprender
  • export e import { … } nomeados.
  • Por que o import termina em .js mesmo apontando para um .ts.
  • export default, import * as e reexportação.
  • import type e o verbatimModuleSyntax.

1. Exportar e importar

Crie dois arquivos. O matematica.ts exporta uma função, uma constante e um tipo:

export const PI_APROX = 3.14;

export function areaCirculo(raio: number): number {
  return PI_APROX * raio * raio;
}

export type Ponto = { x: number; y: number };

function segredo() {
  return "não exportado";
}

O main.ts importa o que precisa:

import { areaCirculo, PI_APROX } from "./matematica.js";
import type { Ponto } from "./matematica.js";

const p: Ponto = { x: 1, y: 2 };
console.log(PI_APROX, areaCirculo(2));
console.log(p);
$ npx tsc && node dist/main.js
3.14 12.56
{ x: 1, y: 2 }
$ ls dist

Cada .ts de src/ virou um .js em dist/, e o node dist/main.js carregou o matematica.js sozinho. Os arquivos .d.ts e .map vêm das opções declaration e sourceMap do tsconfig.json (veja a aula de tsconfig).

Por que ".js" se o arquivo é ".ts"?

O caminho do import é o que vai existir quando o programa rodar: lá em dist/ só há .js. O TypeScript entende que ./matematica.js se refere ao matematica.ts enquanto confere os tipos.

2. Os erros mais comuns com módulos

import { areaCirculo } from "./matematica";
import { segredo } from "./matematica.js";
import { areaQuadrado } from "./matematica.js";
import { algo } from "./nao-existe.js";
$ npx tsc
src/main.ts(1,29): error TS2835: Relative import paths need explicit file extensions in ECMAScript imports when '--moduleResolution' is 'node16' or 'nodenext'. Did you mean './matematica.js'?
src/main.ts(2,10): error TS2459: Module '"./matematica.js"' declares 'segredo' locally, but it is not exported.
src/main.ts(3,10): error TS2305: Module '"./matematica.js"' has no exported member 'areaQuadrado'.
src/main.ts(4,22): error TS2307: Cannot find module './nao-existe.js' or its corresponding type declarations.
  • TS2835: faltou a extensão; a mensagem já sugere ./matematica.js.
  • TS2459: segredo existe, mas não foi exportado.
  • TS2305: o módulo não exporta esse nome.
  • TS2307: o arquivo não existe.

3. import type e verbatimModuleSyntax

Tipos não existem no JavaScript gerado. O nosso tsconfig.json liga o verbatimModuleSyntax, que obriga a marcar os imports que são só de tipo. Assim o tsc (e outras ferramentas) sabem que podem apagar a linha:

export type Usuario = { nome: string };
export interface Produto { preco: number }
import { Usuario, Produto } from "./tipos.js";
const u: Usuario = { nome: "Ana" };
console.log(u);
$ npx tsc
src/main.ts(1,10): error TS1484: 'Usuario' is a type and must be imported using a type-only import when 'verbatimModuleSyntax' is enabled.
src/main.ts(1,19): error TS1484: 'Produto' is a type and must be imported using a type-only import when 'verbatimModuleSyntax' is enabled.

O erro TS1484 aparece uma vez para cada nome. As duas formas certas: import type { Usuario, Produto } from "./tipos.js"; ou, misturando valores e tipos, import { type Usuario, algumValor } from "…";.

4. export default, import * as e reexportação

export default function saudar(nome: string): string {
  return `Olá, ${nome}!`;
}
export const kmParaMilhas = (km: number) => km * 0.621371;
export const celsiusParaF = (c: number) => c * 1.8 + 32;
export { default as saudar } from "./saudacao.js";
export * from "./conversao.js";
import saudar from "./saudacao.js";
import * as conv from "./conversao.js";
import { celsiusParaF } from "./index.js";

console.log(saudar("Bia"));
console.log(conv.kmParaMilhas(10).toFixed(2));
console.log(celsiusParaF(25));
$ npx tsc && node dist/main.js
Olá, Bia!

  • export default: um valor “principal” por arquivo; quem importa escolhe o nome (import saudar from …), sem chaves.
  • import * as conv: junta tudo o que o módulo exporta num objeto.
  • index.ts com export … from: um arquivo que reexporta os outros, para quem importa ter um endereço só.

Quando dá errado

Importar o default com chaves 
import { saudar } from "./saudacao.js";
$ npx tsc
src/main.ts(1,10): error TS2614: Module '"./saudacao.js"' has no exported member 'saudar'. Did you mean to use 'import saudar from "./saudacao.js"' instead?

O TS2614 já sugere a correção: o default se importa sem chaves: import saudar from "./saudacao.js".

Referência rápida

EscritaO que faz
export function f() {}exporta com nome
import { f } from "./a.js"importa pelo nome
export default … / import x from "./a.js"exporta/importa o principal
import * as a from "./a.js"tudo num objeto
import type { T } from "./a.js"só tipos (apagado no JS)
export * from "./a.js"reexporta tudo

Resumo

  • export mostra; import { … } from "./arquivo.js" usa. O .js é obrigatório no nosso projeto.
  • export default se importa sem chaves; import * as junta tudo.
  • Com verbatimModuleSyntax, tipos se importam com import type.
  • Erros comuns: TS2835, TS2459, TS2305, TS2307, TS1484.
