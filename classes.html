Classes e Modificadores

Uma classe é um molde para criar objetos do mesmo tipo, com dados (campos) e comportamento (métodos). O TypeScript acrescenta às classes do JavaScript os tipos e os modificadores de acesso, que dizem quem pode mexer em cada campo.

Você vai aprender
  • Campos tipados, construtor e métodos.
  • public, private, protected e readonly.
  • O atalho das propriedades de parâmetro: constructor(private saldo: number).
  • get/set, static e o #campo privado do JavaScript.

1. Uma classe simples

class Conta {
  titular: string;
  saldo: number;

  constructor(titular: string, saldoInicial: number) {
    this.titular = titular;
    this.saldo = saldoInicial;
  }

  depositar(valor: number): void {
    this.saldo += valor;
  }

  extrato(): string {
    return `${this.titular}: R$ ${this.saldo.toFixed(2)}`;
  }
}

const c = new Conta("Ana", 100);
c.depositar(50);
console.log(c.extrato());
$ npx tsc && node dist/conta.js
Ana: R$ 150.00

Com o strict, todo campo precisa receber valor no construtor (ou ter um valor inicial). Esquecer dá erro:

class Conta {
  titular: string;
  saldo: number;
  constructor(titular: string) {
    this.titular = titular;
  }
}
$ npx tsc
src/sem-valor.ts(3,3): error TS2564: Property 'saldo' has no initializer and is not definitely assigned in the constructor.

2. private, protected, public e readonly

ModificadorQuem pode acessar
public (padrão)qualquer um
privatesó a própria classe
protecteda classe e as subclasses (aula Herança)
readonlylê à vontade, mas só atribui no construtor
class Conta {
  readonly numero: number;
  private saldo: number;

  constructor(numero: number, saldo: number) {
    this.numero = numero;
    this.saldo = saldo;
  }

  sacar(valor: number): boolean {
    if (valor > this.saldo) return false;
    this.saldo -= valor;
    return true;
  }

  verSaldo(): number {
    return this.saldo;
  }
}

const c = new Conta(1234, 100);
console.log(c.sacar(30), c.verSaldo());
console.log(c.sacar(500), c.verSaldo());

c.saldo = 1000000;
c.numero = 9999;
$ npx tsc
src/modificadores.ts(25,3): error TS2341: Property 'saldo' is private and only accessible within class 'Conta'.
src/modificadores.ts(26,3): error TS2540: Cannot assign to 'numero' because it is a read-only property.

O private protege o saldo: só dá para mexer pelos métodos, que conferem as regras. Tirando as duas últimas linhas, o programa roda:

$ npx tsc && node dist/modificadores.js
true 70
false 70

3. O atalho: propriedades de parâmetro

Escrever o campo, o parâmetro e o this.x = x é repetitivo. Pondo o modificador no parâmetro do construtor, o TypeScript cria o campo e faz a atribuição sozinho:

class Produto {
  constructor(
    public readonly nome: string,
    private preco: number,
  ) {}

  comDesconto(pct: number): number {
    return this.preco * (1 - pct / 100);
  }
}

const p = new Produto("Fone", 200);
console.log(p.nome, p.comDesconto(10));
$ npx tsc && node dist/atalho.js
Fone 180
class Produto {
    nome;
    preco;
    constructor(nome, preco) {
        this.nome = nome;
        this.preco = preco;
    }
    comDesconto(pct) {
        return this.preco * (1 - pct / 100);
    }
}
const p = new Produto("Fone", 200);
console.log(p.nome, p.comDesconto(10));
export {};
//# sourceMappingURL=atalho.js.map

No JavaScript gerado, o tsc escreveu os campos e as atribuições por você.

4. get, set e static

class Temperatura {
  static zeroAbsoluto = -273.15;
  private celsius = 0;

  get fahrenheit(): number {
    return this.celsius * 1.8 + 32;
  }

  set graus(valor: number) {
    if (valor < Temperatura.zeroAbsoluto) {
      throw new Error("abaixo do zero absoluto");
    }
    this.celsius = valor;
  }
}

const t = new Temperatura();
t.graus = 25;
console.log(t.fahrenheit);
console.log(Temperatura.zeroAbsoluto);
$ npx tsc && node dist/get-set.js
77
-273.15

O get se lê como um campo (t.fahrenheit, sem parênteses) e o set se usa com =. O static pertence à classe, não aos objetos: Temperatura.zeroAbsoluto.

5. private do TypeScript x #privado do JavaScript

O private é só uma regra do compilador: no JavaScript gerado, o campo continua acessível. Já o #campo é privado de verdade, também rodando:

class Cofre {
  private segredoTs = "ts";
  #segredoJs = "js";

  revelar() {
    return this.#segredoJs;
  }
}

const c = new Cofre();
console.log((c as any).segredoTs);
console.log((c as any)["#segredoJs"]);
console.log(c.revelar());
$ npx tsc && node dist/hash.js
ts
undefined
js

O as any “desliga” o compilador (aula Asserções) e mostra a diferença: o private vazou (ts), o #segredoJs não (undefined).

Quando dá errado

Esquecer o this 
class Contador {
  total = 0;
  somar() {
    total++;
  }
}
$ npx tsc
src/sem-this.ts(4,5): error TS2663: Cannot find name 'total'. Did you mean the instance member 'this.total'?

Dentro do método, o campo é this.total.

Esquecer o new 
class Ponto {
  constructor(public x: number, public y: number) {}
}
const p = Ponto(1, 2);
$ npx tsc
src/sem-new.ts(4,11): error TS2348: Value of type 'typeof Ponto' is not callable. Did you mean to include 'new'?

3. Da classe

Complete para o campo pertencer à classe, e não aos objetos:

Resumo

  • Classes têm campos tipados (com valor garantido pelo construtor) e métodos.
  • private, protected, public e readonly controlam o acesso, na hora de compilar.
  • constructor(private x: number) cria e preenche o campo sozinho.
  • #campo é privado também no JavaScript rodando.
