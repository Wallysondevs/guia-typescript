2. Os tipos

Comece pelo “vocabulário” do programa. Repare no Resultado: uma union discriminada pelo campo ok, para as funções avisarem sucesso ou erro sem lançar exceções.

export type Prioridade = "baixa" | "media" | "alta";

export interface Tarefa {
  id: number;
  titulo: string;
  prioridade: Prioridade;
  feita: boolean;
}

export type Resultado<T> =
  | { ok: true; valor: T }
  | { ok: false; erro: string };

3. Ler e gravar o arquivo

O conteúdo de um JSON chega como unknown para nós: pode ter sido editado à mão, pode estar estragado. Um type guard confere a forma antes de confiar.

import { existsSync, readFileSync, writeFileSync } from "node:fs";
import type { Tarefa } from "./tipos.js";

const ARQUIVO = "tarefas.json";

function ehTarefa(x: unknown): x is Tarefa {
  return (
    typeof x === "object" && x !== null &&
    "id" in x && typeof x.id === "number" &&
    "titulo" in x && typeof x.titulo === "string" &&
    "prioridade" in x && (x.prioridade === "baixa" || x.prioridade === "media" || x.prioridade === "alta") &&
    "feita" in x && typeof x.feita === "boolean"
  );
}

export function carregar(): Tarefa[] {
  if (!existsSync(ARQUIVO)) return [];
  const dados: unknown = JSON.parse(readFileSync(ARQUIVO, "utf8"));
  if (!Array.isArray(dados)) return [];
  return dados.filter(ehTarefa);
}

export function salvar(lista: Tarefa[]): void {
  writeFileSync(ARQUIVO, JSON.stringify(lista, null, 2) + "\n");
}

4. As regras

As funções não mexem no arquivo: recebem a lista e devolvem um Resultado com a lista nova. Isso deixa tudo fácil de testar.

import type { Prioridade, Resultado, Tarefa } from "./tipos.js";

const PRIORIDADES: readonly Prioridade[] = ["baixa", "media", "alta"];

export function ehPrioridade(x: string): x is Prioridade {
  return (PRIORIDADES as readonly string[]).includes(x);
}

export function adicionar(lista: Tarefa[], titulo: string, prioridade: Prioridade): Resultado<Tarefa[]> {
  if (titulo.trim() === "") return { ok: false, erro: "o título não pode ser vazio" };
  const id = Math.max(0, ...lista.map((t) => t.id)) + 1;
  return { ok: true, valor: [...lista, { id, titulo: titulo.trim(), prioridade, feita: false }] };
}

export function concluir(lista: Tarefa[], id: number): Resultado<Tarefa[]> {
  if (!lista.some((t) => t.id === id)) return { ok: false, erro: `tarefa ${id} não existe` };
  return { ok: true, valor: lista.map((t) => (t.id === id ? { ...t, feita: true } : t)) };
}

export function remover(lista: Tarefa[], id: number): Resultado<Tarefa[]> {
  const nova = lista.filter((t) => t.id !== id);
  if (nova.length === lista.length) return { ok: false, erro: `tarefa ${id} não existe` };
  return { ok: true, valor: nova };
}

export function formatar(t: Tarefa): string {
  const marca = t.feita ? "[x]" : "[ ]";
  let sinal: string;
  switch (t.prioridade) {
    case "alta":
      sinal = "!!!";
      break;
    case "media":
      sinal = "!!";
      break;
    case "baixa":
      sinal = "!";
      break;
    default:
      const nunca: never = t.prioridade;
      throw new Error("prioridade inválida: " + nunca);
  }
  return `${marca} ${t.id}. ${t.titulo} ${sinal}`;
}

5. O ponto de entrada

O index.ts lê os argumentos do terminal (process.argv), chama a regra certa e trata o Resultado.

import { carregar, salvar } from "./armazenamento.js";
import { adicionar, concluir, ehPrioridade, formatar, remover } from "./tarefas.js";
import type { Resultado, Tarefa } from "./tipos.js";

const [comando, ...args] = process.argv.slice(2);
const lista = carregar();

function aplicar(r: Resultado<Tarefa[]>, mensagem: string): void {
  if (!r.ok) {
    console.log("Erro: " + r.erro);
    process.exitCode = 1;
    return;
  }
  salvar(r.valor);
  console.log(mensagem);
}

switch (comando) {
  case "adicionar": {
    const titulo = args[0] ?? "";
    const prioridade = args[1] ?? "media";
    if (!ehPrioridade(prioridade)) {
      console.log(`Erro: prioridade "${prioridade}" inválida (use baixa, media ou alta)`);
      process.exitCode = 1;
      break;
    }
    aplicar(adicionar(lista, titulo, prioridade), `Adicionada: ${titulo}`);
    break;
  }
  case "concluir":
    aplicar(concluir(lista, Number(args[0])), `Concluída: ${args[0]}`);
    break;
  case "remover":
    aplicar(remover(lista, Number(args[0])), `Removida: ${args[0]}`);
    break;
  case "listar":
  case undefined:
    if (lista.length === 0) console.log("Nenhuma tarefa. Que tal adicionar uma?");
    for (const t of lista) console.log(formatar(t));
    break;
  default:
    console.log(`Comando desconhecido: ${comando}`);
    console.log("Use: adicionar, listar, concluir ou remover");
    process.exitCode = 1;
}

Cada caso de erro foi previsto nos tipos: Resultado obriga a tratar a falha, o type guard ehPrioridade barra a prioridade inválida e o default do switch pega comandos desconhecidos.

O compilador de guarda

Imagine que alguém acrescenta uma prioridade nova, "urgente", em tipos.ts, e esquece do resto:

export type Prioridade = "baixa" | "media" | "alta" | "urgente";
$ npm run build -s
src/tarefas.ts(40,13): error TS2322: Type '"urgente"' is not assignable to type 'never'.

O never do formatar apontou exatamente onde falta tratar o caso novo. Antes de o programa rodar, o TypeScript já mostrou o que falta. Esse é o espírito do guia inteiro.
