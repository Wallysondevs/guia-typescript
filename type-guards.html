Type Guards Customizados

O typeof e o instanceof resolvem os casos simples. Para conferir algo mais complexo (“isto é um Usuario válido?”), você escreve a sua própria função de conferência, e diz ao compilador o que ela garante com x is Tipo. Assim, o narrowing da aula Narrowing passa a funcionar com as suas regras.

Você vai aprender
  • A escrever um type guard: function ehUsuario(x: unknown): x is Usuario.
  • A validar dados unknown (como um JSON) sem asserção.
  • A filtrar arrays com um guard.
  • Funções de asserção: asserts x is Tipo.

1. Por que uma função booleana comum não basta

type Gato = { miar(): string };
type Peixe = { nadar(): string };

function ehGato(a: Gato | Peixe): boolean {
  return "miar" in a;
}

function agir(a: Gato | Peixe) {
  if (ehGato(a)) {
    return a.miar();
  }
  return "...";
}
$ npx tsc
src/booleana.ts(10,14): error TS2339: Property 'miar' does not exist on type 'Gato | Peixe'.
  Property 'miar' does not exist on type 'Peixe'.

A função devolve boolean, e o compilador não sabe o que esse true significa. Dentro do if, a continua Gato | Peixe.

2. O predicado de tipo: a is Gato

type Gato = { miar(): string };
type Peixe = { nadar(): string };

function ehGato(a: Gato | Peixe): a is Gato {
  return "miar" in a;
}

function agir(a: Gato | Peixe) {
  if (ehGato(a)) {
    return a.miar();
  }
  return a.nadar();
}

console.log(agir({ miar: () => "Miau" }));
console.log(agir({ nadar: () => "glub glub" }));
$ npx tsc && node dist/guard.js
Miau
glub glub

O a is Gato no lugar do boolean diz: “se eu devolver true, a é Gato”. E o compilador estreita nos dois lados: no if é Gato, depois dele só sobra Peixe.

3. Validando dados de fora

O uso mais importante: conferir de verdade um valor unknown, em vez de afirmar com as (que, como você viu em Asserções, pode mentir):

type Usuario = { nome: string; idade: number };

function ehUsuario(x: unknown): x is Usuario {
  return (
    typeof x === "object" &&
    x !== null &&
    "nome" in x &&
    typeof x.nome === "string" &&
    "idade" in x &&
    typeof x.idade === "number"
  );
}

const entradas = ['{"nome": "Ana", "idade": 30}', '{"nome": "Duda"}', '"só um texto"'];

for (const texto of entradas) {
  const dados: unknown = JSON.parse(texto);
  if (ehUsuario(dados)) {
    console.log(`ok: ${dados.nome} tem ${dados.idade} anos`);
  } else {
    console.log("inválido:", texto);
  }
}
$ npx tsc && node dist/validar.js
ok: Ana tem 30 anos
inválido: {"nome": "Duda"}
inválido: "só um texto"

Repare que dentro do guard o compilador acompanha cada passo: depois de "nome" in x, ele deixa ler x.nome. O {"nome": "Duda"}, sem idade, foi recusado rodando, em vez de virar um erro mais adiante.

Responsabilidade sua

O compilador confia no que o guard devolve. Se a função disser true para algo errado, o tipo vai mentir. Escreva o guard com cuidado e confira todos os campos que importam.

4. Filtrando arrays

const misturado = [3, "a", 7, null, "b", 10];

const soNumeros = misturado.filter((x): x is number => typeof x === "number");
const soma = soNumeros.reduce((a, b) => a + b, 0);
console.log(soNumeros, soma);

function existe<T>(x: T | null | undefined): x is T {
  return x !== null && x !== undefined;
}
const nomes = ["Ana", null, "Duda", undefined].filter(existe);
console.log(nomes.map((n) => n.toUpperCase()));
$ npx tsc && node dist/filtrar.js
[ 3, 7, 10 ] 20
[ 'ANA', 'DUDA' ]

Com o guard, o filter devolve um array do tipo certo (number[], string[]), e não mais a mistura.

5. Funções de asserção: asserts

Uma função de asserção não devolve nada: ela lança um erro se a condição falhar. Depois da chamada, o compilador considera a condição verdadeira:

function garantirTexto(x: unknown): asserts x is string {
  if (typeof x !== "string") {
    throw new Error("esperava um texto, veio " + typeof x);
  }
}

function gritar(valor: unknown) {
  garantirTexto(valor);
  return valor.toUpperCase() + "!";
}

console.log(gritar("oba"));
try {
  console.log(gritar(42));
} catch (e) {
  console.log("Pegou:", (e as Error).message);
}
$ npx tsc && node dist/asserts.js
OBA!
Pegou: esperava um texto, veio number

Quando dá errado

Predicado com um tipo que não cabe no parâmetro 
function ehTexto(x: number): x is string {
  return false;
}
$ npx tsc
src/predicado-erro.ts(1,35): error TS2677: A type predicate's type must be assignable to its parameter's type.
  Type 'string' is not assignable to type 'number'.

O tipo do predicado precisa ser um caso possível do parâmetro.

Missão: escreva o guard function ehQuadrado(f: Quadrado | Circulo): f is Quadrado (confira "lado" in f) e use em area. Mostre área do quadrado: 16 e área do círculo: 3.14.

type Quadrado = { lado: number };
type Circulo = { raio: number };

function area(f: Quadrado | Circulo): string {
  return "?";
}
console.log(area({ lado: 4 }));
console.log(area({ raio: 1 }));

type Quadrado = { lado: number };
type Circulo = { raio: number };

function ehQuadrado(f: Quadrado | Circulo): f is Quadrado {
  return "lado" in f;
}
function area(f: Quadrado | Circulo): string {
  if (ehQuadrado(f)) return "área do quadrado: " + f.lado ** 2;
  return "área do círculo: " + (Math.PI * f.raio ** 2).toFixed(2);
}
console.log(area({ lado: 4 }));
console.log(area({ raio: 1 }));

área do quadrado: 16
área do círculo: 3.14

Missão: filtre só os textos da lista usando um guard direto no filter: (x): x is string => typeof x === "string". Mostre o array resultante.

const itens = ["ana", 1, "duda", true];
const textos = itens.filter((x) => true);
console.log(textos);

const itens = ["ana", 1, "duda", true];
const textos = itens.filter((x): x is string => typeof x === "string");
console.log(textos);

[ 'ana', 'duda' ]

Resumo

  • Um type guard devolve x is Tipo: o compilador estreita conforme o resultado.
  • Para dados de fora, unknown + guard é mais seguro que as.
  • Guards no filter devolvem arrays do tipo certo.
  • asserts x is Tipo: lança erro se falhar; depois da chamada, o tipo está garantido.
