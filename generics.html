Generics

Às vezes uma função funciona igual para qualquer tipo: pegar o primeiro item de uma lista, embrulhar um valor numa caixa. Com any, você perde o tipo no caminho. Com generics, o tipo vira um parâmetro (<T>): entra número, sai número; entra texto, sai texto.

Você vai aprender
  • Por que any não resolve, com um erro que só aparece rodando.
  • Funções genéricas: function primeiro<T>(lista: T[]): T | undefined.
  • Como o TypeScript infere o T e como passá-lo à mão.
  • Types, interfaces e classes genéricas.

1. O problema com any

function primeiro(lista: any[]): any {
  return lista[0];
}

const n = primeiro([10, 20, 30]);
console.log(n.toUpperCase());

2. A versão genérica

function primeiro
o nome da função
<T>
o parâmetro de tipo: um “espaço” que será preenchido com um tipo
(lista: T[])
recebe uma lista de T
: T | undefined
devolve um T (ou undefined, se a lista estiver vazia)
function primeiro<T>(lista: T[]): T | undefined {
  return lista[0];
}

const n = primeiro([10, 20, 30]);
const s = primeiro(["ana", "bia"]);
console.log(n, s);

const erro: string = primeiro([10, 20, 30]);
$ npx tsc
src/generico.ts(9,7): error TS2322: Type 'number | undefined' is not assignable to type 'string'.
  Type 'undefined' is not assignable to type 'string'.

Ninguém escreveu o T na chamada: o TypeScript olhou o argumento [10, 20, 30] e concluiu T = number. Por isso ele sabe que o resultado é number | undefined e não deixa guardar numa string.

Também dá para passar o tipo à mão, entre < >:

function embrulhar<T>(valor: T): T[] {
  return [valor];
}
const a = embrulhar<string>("oi");
const b = embrulhar(42);
console.log(a, b);
const c = embrulhar<string>(42);
$ npx tsc
src/explicito.ts(7,29): error TS2345: Argument of type 'number' is not assignable to parameter of type 'string'.

3. Mais de um parâmetro de tipo

function par<A, B>(a: A, b: B): [A, B] {
  return [a, b];
}

function mapear<T, R>(lista: T[], fn: (item: T) => R): R[] {
  const saida: R[] = [];
  for (const item of lista) saida.push(fn(item));
  return saida;
}

console.log(par("Ana", 30));
console.log(mapear([1, 2, 3], (n) => "#" + n));
console.log(mapear(["ana", "bia"], (s) => s.length));
$ npx tsc && node dist/par.js
[ 'Ana', 30 ]
[ '#1', '#2', '#3' ]
[ 3, 3 ]

É assim que o map dos arrays é tipado: entra uma lista de T, sai uma lista de R, o que a sua função devolver.

4. Types e interfaces genéricas

type Resposta<T> = {
  ok: boolean;
  dados: T;
};

interface Caixa<T> {
  conteudo: T;
  rotulo: string;
}

const r1: Resposta<number[]> = { ok: true, dados: [1, 2, 3] };
const r2: Resposta<{ nome: string }> = { ok: true, dados: { nome: "Ana" } };
const cx: Caixa<boolean> = { conteudo: true, rotulo: "ligado?" };

console.log(r1.dados.length, r2.dados.nome, cx.conteudo);
$ npx tsc && node dist/tipos-genericos.js
3 Ana true

Você já usava um tipo genérico sem saber: Array<number>. Outros comuns: Promise<T> (aula async/await), Map<K, V> e Set<T>.

5. Classes genéricas

class Pilha<T> {
  private itens: T[] = [];

  empilhar(item: T): void {
    this.itens.push(item);
  }

  desempilhar(): T | undefined {
    return this.itens.pop();
  }

  get tamanho(): number {
    return this.itens.length;
  }
}

const pratos = new Pilha<string>();
pratos.empilhar("azul");
pratos.empilhar("verde");
console.log(pratos.desempilhar(), pratos.tamanho);

const numeros = new Pilha<number>();
numeros.empilhar(1);
numeros.empilhar("dois");
$ npx tsc
src/pilha.ts(24,18): error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.

Quando dá errado

Usar propriedades que o T pode não ter 
function tamanho<T>(x: T): number {
  return x.length;
}
$ npx tsc
src/t-sem-length.ts(2,12): error TS2339: Property 'length' does not exist on type 'T'.

O T pode ser qualquer coisa, inclusive um número, que não tem length. A solução é restringir o T: assunto da próxima aula, Restrições em Generics.

Missões

Missão: escreva function ultimo<T>(lista: T[]): T | undefined, que devolve o último item, e mostre o resultado para [10, 20, 30] e para ["ana", "bia"].

function ultimo(lista: any[]): any {
  return lista[lista.length - 1];
}

function ultimo<T>(lista: T[]): T | undefined {
  return lista[lista.length - 1];
}
console.log(ultimo([10, 20, 30]));
console.log(ultimo(["ana", "bia"]));

30
bia

Missão: complete a class Fila<T> com entrar(item: T) e sair(): T | undefined (use shift()). Com uma fila de textos, faça "Ana" e "Bia" entrarem, e mostre primeiro: Ana e restam: 1.

class Fila {
  itens: any[] = [];
}

class Fila<T> {
  private itens: T[] = [];
  entrar(item: T): void {
    this.itens.push(item);
  }
  sair(): T | undefined {
    return this.itens.shift();
  }
  get tamanho(): number {
    return this.itens.length;
  }
}
const f = new Fila<string>();
f.entrar("Ana");
f.entrar("Bia");
console.log("primeiro: " + f.sair());
console.log("restam: " + f.tamanho);

primeiro: Ana
restam: 1

Missão: use o tipo genérico Resposta<T> com T = string[] para tipar r e mostre 2 nomes: Ana, Bia usando r.dados.

type Resposta<T> = { ok: boolean; dados: T };
const r = { ok: true, dados: ["Ana", "Bia"] };

type Resposta<T> = { ok: boolean; dados: T };
const r: Resposta<string[]> = { ok: true, dados: ["Ana", "Bia"] };
console.log(`${r.dados.length} nomes: ${r.dados.join(", ")}`);

2 nomes: Ana, Bia

Resumo

  • Generics transformam o tipo num parâmetro: <T>.
  • O T costuma ser inferido pelos argumentos; dá para passar à mão com f<string>(…).
  • Types, interfaces e classes também podem ser genéricos: Resposta<T>, Pilha<T>.
  • Diferente de any, o compilador continua conferindo tudo.
