null, undefined e ?.

O erro mais comum do JavaScript é tentar usar algo que não existe: Cannot read properties of undefined. Com o modo strict, o TypeScript trata null e undefined como tipos separados e obriga você a pensar neles. Nesta aula você aprende as ferramentas para isso: ?., ?? e o narrowing.

Você vai aprender
  • O que o strictNullChecks (parte do strict) faz.
  • O encadeamento opcional ?..
  • A coalescência nula ?? e o ??=.
  • A diferença entre ?? e ||.

1. O erro que o JavaScript deixa passar

Em JavaScript, este código roda e quebra:

const usuarios = [{ nome: "Ana" }, { nome: "Duda" }];
const achado = usuarios.find((u) => u.nome === "Caio");
console.log(achado.nome);
$ node busca.js
file:///home/ana/projeto/busca.js:3
console.log(achado.nome);
                   ^

TypeError: Cannot read properties of undefined (reading 'nome')
    at file:///home/ana/projeto/busca.js:3:20
    at ModuleJob.run (node:internal/modules/esm/module_job:561:25)
    at async node:internal/modules/esm/loader:647:26
    at async asyncRunEntryPointWithESMLoader (node:internal/modules/run_main:101:5)

Node.js v24.22.1

Em TypeScript, o mesmo código nem compila. O find devolve { nome: string } | undefined, porque pode não achar:

const usuarios = [{ nome: "Ana" }, { nome: "Duda" }];
const achado = usuarios.find((u) => u.nome === "Caio");
console.log(achado.nome);
$ npx tsc
src/busca.ts(3,13): error TS18048: 'achado' is possibly 'undefined'.

2. Encadeamento opcional: ?.

O ?. lê a propriedade só se o valor existir. Se for null ou undefined, o resultado é undefined, sem erro:

type Usuario = { nome: string; endereco?: { cidade: string } };

const ana: Usuario = { nome: "Ana", endereco: { cidade: "Recife" } };
const duda: Usuario = { nome: "Duda" };

console.log(ana.endereco?.cidade);
console.log(duda.endereco?.cidade);

function carregarLista(): string[] | undefined {
  return undefined;
}
const lista = carregarLista();
console.log(lista?.length);
console.log(lista?.[0]);
$ npx tsc && node dist/opcional.js
Recife
undefined
undefined
undefined

Funciona também com índices (?.[0]) e chamadas de função (fn?.()).

3. Valor padrão: ??

O ?? usa o valor da direita quando o da esquerda é null ou undefined. Juntando com o ?.:

type Usuario = { nome: string; endereco?: { cidade: string }; pontos?: number };

function cidadeDe(u: Usuario): string {
  return u.endereco?.cidade ?? "cidade não informada";
}

console.log(cidadeDe({ nome: "Ana", endereco: { cidade: "Recife" } }));
console.log(cidadeDe({ nome: "Duda" }));

const config: { tema?: string } = {};
config.tema ??= "claro";
console.log(config.tema);
$ npx tsc && node dist/coalescencia.js
Recife
cidade não informada
claro

O ??= atribui só se o valor atual for null ou undefined.

4. ?? não é ||

O || troca qualquer valor “falso”: também 0, "" e false. O ?? troca só null e undefined:

const pontos = 0;
const apelido = "";

console.log("com ||:", pontos || 10, JSON.stringify(apelido || "sem apelido"));
console.log("com ??:", pontos ?? 10, JSON.stringify(apelido ?? "sem apelido"));
$ npx tsc && node dist/ou.js
com ||: 10 "sem apelido"
com ??: 0 ""

Com ||, os zero pontos viraram 10. Quando 0 ou "" são valores válidos, use ??.

5. null de propósito

Use null quando “nada” é uma resposta válida, e escreva isso no tipo:

function buscarTelefone(nome: string): string | null {
  if (nome === "Ana") return "81 99999-0000";
  return null;
}

const tel = buscarTelefone("Duda");
if (tel === null) {
  console.log("sem telefone");
} else {
  console.log(tel.replace(" ", "-"));
}
console.log(buscarTelefone("Ana")?.length);
$ npx tsc && node dist/null.js
sem telefone
13

Quando dá errado

Atribuir null a um tipo que não aceita 
let nome: string = null;
let idade: number = undefined;
$ npx tsc
src/null-erro.ts(1,5): error TS2322: Type 'null' is not assignable to type 'string'.
src/null-erro.ts(2,5): error TS2322: Type 'undefined' is not assignable to type 'number'.

Com o strict, null e undefined não cabem em string nem em number. Se o valor pode faltar, diga no tipo: string | null.

?. do lado esquerdo de uma atribuição 
const u: { endereco?: { cidade: string } } = {};
u.endereco?.cidade = "Natal";
$ npx tsc
src/atribuir.ts(2,1): error TS2779: The left-hand side of an assignment expression may not be an optional property access.

O ?. serve só para ler. Para escrever, confira antes com if.

Referência rápida

EscritaSignificado
a?.ba.b, ou undefined se a for null/undefined
a?.[0] / f?.()o mesmo para índice e chamada
a ?? bb só se a for null/undefined
a ??= batribui b se a for null/undefined
a || bb se a for qualquer valor falso (0, "", false…)

Missões

Missão: corrija o código usando ?. e ?? para mostrar o nome encontrado (Duda) e, para o id que não existe, não encontrado.

const pessoas = [{ id: 1, nome: "Ana" }, { id: 2, nome: "Duda" }];
function nomeDe(id: number): string {
  return pessoas.find((p) => p.id === id).nome;
}
console.log(nomeDe(2));
console.log(nomeDe(9));

const pessoas = [{ id: 1, nome: "Ana" }, { id: 2, nome: "Duda" }];
function nomeDe(id: number): string {
  return pessoas.find((p) => p.id === id)?.nome ?? "não encontrado";
}
console.log(nomeDe(2));
console.log(nomeDe(9));

Duda
não encontrado

Missão: o volume 0 está virando 50 por causa do ||. Troque por ?? para mostrar volume: 0 e, quando não vier nada, volume: 50.

function ajustar(volume?: number) {
  console.log("volume: " + (volume || 50));
}
ajustar(0);
ajustar();

function ajustar(volume?: number) {
  console.log("volume: " + (volume ?? 50));
}
ajustar(0);
ajustar();

volume: 0
volume: 50

Resumo

  • Com strict, null e undefined só entram onde o tipo diz.
  • ?. lê com segurança; ?? dá um padrão para null/undefined; ??= atribui se faltar.
  • || troca qualquer valor falso, inclusive 0 e ""; prefira ??.
