Decorators

Um decorator é uma função que você “pendura” numa classe ou num método com @nome, para acrescentar comportamento sem mexer no código de dentro: registrar chamadas, medir tempo, validar, cadastrar classes. Frameworks como Angular e NestJS usam muito. Nesta aula você escreve os seus, com os decorators padrão do JavaScript que o TypeScript entende.

Você vai aprender
  • Por que é preciso --target es2022 (ou outro target abaixo de esnext) no Node 24.
  • Decorators de método, com ClassMethodDecoratorContext.
  • Decorators de classe e o addInitializer.
  • Decorators com parâmetros (fábricas).

1. Primeiro problema: o target

Um decorator de método que mostra cada chamada:

function registrar(metodo: (...args: any[]) => any, contexto: ClassMethodDecoratorContext) {
  return function (this: unknown, ...args: any[]) {
    console.log(`chamando ${String(contexto.name)}(${args.join(", ")})`);
    return metodo.apply(this, args);
  };
}

class Calculadora {
  @registrar
  somar(a: number, b: number) {
    return a + b;
  }
}

console.log(new Calculadora().somar(2, 3));

Compilou, mas o Node recusou o @. Com "target": "esnext", o tsc deixa os decorators como estão, porque eles fazem parte do JavaScript do futuro, e o Node 24 ainda não os entende. A solução é pedir um target mais antigo, que faz o tsc converter os decorators em código comum:

$ npx tsc --target es2022 && node dist/log.js
chamando somar(2, 3)
5

Para não digitar sempre, troque no tsconfig.json a linha "target": "esnext" por "target": "es2022". Nesta aula usamos a opção na linha de comando.

2. Anatomia de um decorator de método

metodo
o método original.
contexto: ClassMethodDecoratorContext
informações sobre onde o decorator foi usado: contexto.name (o nome do método), contexto.kind ("method"), contexto.static, contexto.addInitializer…
return function (…) { … }
o método novo, que substitui o original. Aqui ele mostra a chamada e chama o original com metodo.apply(this, args).

Um decorator pode ser usado em vários métodos. Um medidor de execuções:

function contar(metodo: (...args: any[]) => any, contexto: ClassMethodDecoratorContext) {
  let vezes = 0;
  return function (this: unknown, ...args: any[]) {
    vezes++;
    console.log(`${String(contexto.name)} chamado ${vezes}x`);
    return metodo.apply(this, args);
  };
}

class Carrinho {
  itens: string[] = [];

  @contar
  adicionar(item: string) {
    this.itens.push(item);
  }

  @contar
  limpar() {
    this.itens = [];
  }
}

const c = new Carrinho();
c.adicionar("pão");
c.adicionar("leite");
c.limpar();
console.log(c.itens);
$ npx tsc --target es2022 && node dist/contador.js
adicionar chamado 1x
adicionar chamado 2x
limpar chamado 1x
[]

3. Decorators com parâmetros

Para configurar o decorator (@prefixo("[API]")), escreva uma função que devolve o decorator:

function prefixo(texto: string) {
  return function (metodo: (...args: any[]) => string, contexto: ClassMethodDecoratorContext) {
    return function (this: unknown, ...args: any[]): string {
      return `${texto} ${metodo.apply(this, args)}`;
    };
  };
}

class Mensagens {
  @prefixo("[AVISO]")
  aviso(msg: string) {
    return msg;
  }

  @prefixo("[ERRO]")
  erro(msg: string) {
    return msg.toUpperCase();
  }
}

const m = new Mensagens();
console.log(m.aviso("disco quase cheio"));
console.log(m.erro("sem conexão"));
$ npx tsc --target es2022 && node dist/fabrica.js
[AVISO] disco quase cheio
[ERRO] SEM CONEXÃO

4. Decorators de classe e addInitializer

Um decorator de classe recebe a própria classe. Um uso comum é cadastrar classes num registro:

const registro: string[] = [];

function cadastrar(classe: new (...args: any[]) => object, contexto: ClassDecoratorContext) {
  contexto.addInitializer(() => {
    registro.push(String(contexto.name));
  });
}

@cadastrar
class Usuario {}

@cadastrar
class Produto {}

console.log("classes cadastradas:", registro);
console.log(new Usuario(), new Produto());
$ npx tsc --target es2022 && node dist/classe.js
classes cadastradas: [ 'Usuario', 'Produto' ]
Usuario {} Produto {}

O addInitializer roda uma função assim que a classe termina de ser definida, antes de qualquer new.

Quando dá errado

Decorator com a assinatura errada 
function marcar(nome: string) {
  console.log(nome);
}

class Tela {
  @marcar
  abrir() {}
}
$ npx tsc --target es2022
src/assinatura.ts(6,4): error TS1241: Unable to resolve signature of method decorator when called as an expression.
  Argument of type '() => void' is not assignable to parameter of type 'string'.

O TypeScript confere que a função serve como decorator: ela recebe o método e o contexto, não uma string. Se queria passar um texto, faça uma fábrica (seção 3) e use @marcar("tela").

experimentalDecorators

Projetos mais antigos (e alguns frameworks) usam os decorators “experimentais” do TypeScript, ligados com "experimentalDecorators": true, que têm outra assinatura (alvo, chave, descritor). Se o seu framework pedir essa opção, siga a documentação dele; para código novo, use os decorators padrão desta aula.

    return function (this: unknown, ...args: any[]): number {

Resumo

  • Decorator é uma função aplicada com @ que acrescenta comportamento.
  • No Node 24, compile com --target es2022 (o esnext deixa o @ no JS).
  • Método: recebe (metodo, contexto) e devolve o método novo.
  • Classe: recebe (classe, contexto); addInitializer roda ao definir a classe.
  • Com parâmetros: uma função que devolve o decorator.
