Inferência de Tipos

Você não precisa escrever : tipo em tudo. Quando você dá um valor logo na criação, o TypeScript deduz o tipo sozinho. Isso se chama inferência. O código fica limpo e continua conferido.

Você vai aprender
  • Como o TypeScript deduz o tipo pelo valor inicial.
  • A diferença entre let (tipo largo, string) e const (tipo literal, "Ana").
  • Que o retorno das funções também é inferido.
  • Quando a anotação ainda é necessária.

A ideia: o tipo vem do primeiro valor

Se você escreve let idade = 30, o TypeScript pensa: “começou com um número, então é number”. A partir daí, a variável é number para sempre, como se você tivesse escrito a anotação.

let idade = 30;
let nome = "Ana";
let ativo = true;

idade = 31;
idade = "trinta e um";
$ npx tsc
src/inferencia.ts(6,1): error TS2322: Type 'string' is not assignable to type 'number'.

Ninguém escreveu : number, mas o erro TS2322 é o mesmo da aula anterior. A inferência dá a mesma proteção com menos digitação.

1. Vendo o tipo inferido

No editor (como o VS Code), basta parar o mouse sobre a variável para ver o tipo. No terminal, um truque é provocar um erro: o compilador sempre diz o tipo que deduziu. Atribuir a variável a outra do tipo errado revela o tipo:

let preco = 9.9;
let produto = "café";
let lista = [1, 2, 3];

const teste1: boolean = preco;
const teste2: boolean = produto;
const teste3: boolean = lista;
$ npx tsc
src/revela.ts(5,7): error TS2322: Type 'number' is not assignable to type 'boolean'.
src/revela.ts(6,7): error TS2322: Type 'string' is not assignable to type 'boolean'.
src/revela.ts(7,7): error TS2322: Type 'number[]' is not assignable to type 'boolean'.

O lista foi inferido como number[], um array de números (aula Arrays e Tuplas).

2. let ou const muda o tipo

Uma const nunca muda de valor. Por isso o TypeScript infere um tipo literal: não “qualquer texto”, mas exatamente aquele texto.

let cidade = "Brasília";
const capital = "Brasília";

const a: "Brasília" = capital;
const b: "Brasília" = cidade;
$ npx tsc
src/literal.ts(5,7): error TS2322: Type 'string' is not assignable to type '"Brasília"'.

Aqui o tipo "Brasília" (com aspas, na anotação) quer dizer “só este texto exato”. A linha 4 passou: o capital, criado com const, tem o tipo literal "Brasília". A linha 5 falhou: o cidade, criado com let, é uma string qualquer, porque poderia mudar depois. Os tipos literais aparecem de novo na aula Union e Literal Types.

3. O retorno das funções também é inferido

function dobro(n: number) {
  return n * 2;
}

const resultado = dobro(21);
console.log(resultado);

const texto: string = dobro(5);
$ npx tsc
src/retorno.ts(8,7): error TS2322: Type 'number' is not assignable to type 'string'.

O parâmetro n precisou de anotação, mas o retorno não: n * 2 é um número, então dobro devolve number.

4. Quando a anotação é necessária

Sem valor inicial, não há de onde deduzir. Com o strict, um parâmetro sem tipo vira erro:

function saudar(nome) {
  return "Olá, " + nome;
}
console.log(saudar("Ana"));
$ npx tsc
src/sem-tipo.ts(1,17): error TS7006: Parameter 'nome' implicitly has an 'any' type.

O TS7006 diz que o parâmetro ficou com o tipo any (“qualquer coisa”) sem você pedir. Regra prática: anote os parâmetros das funções e deixe a inferência cuidar das variáveis com valor inicial.

Quando dá errado

Mudar uma const 
const pi = 3.14;
pi = 3.14159;
$ npx tsc
src/const.ts(2,1): error TS2588: Cannot assign to 'pi' because it is a constant.

O TS2588 diz que não dá para atribuir a pi porque é uma constante. Use let se o valor precisa mudar.

Variável sem valor e sem tipo 
let total;
total = 10;
total = "dez";
console.log(total);
$ npx tsc && node dist/vazia.js
dez

Aqui não houve erro: um let sem valor e sem tipo vai mudando de tipo conforme as atribuições, o que quase nunca é o que você quer. Dê um valor inicial ou escreva o tipo: let total: number;.

Missão: sem escrever nenhuma anotação, crie let pontos = 100; e depois tente pontos = "cem";. Cole o erro que prova que a inferência funcionou.

let pontos = 100;
console.log(pontos);

let pontos = 100;
pontos = "cem";

src/missao.ts(2,1): error TS2322: Type 'string' is not assignable to type 'number'.

Missão: a função triplo está sem tipo no parâmetro e o tsc reclama. Anote só o parâmetro (n: number), deixe o retorno ser inferido e mostre triplo(7).

function triplo(n) {
  return n * 3;
}
console.log(triplo(7));

function triplo(n: number) {
  return n * 3;
}

Resumo

  • Com valor inicial, o TypeScript deduz o tipo: isso é inferência.
  • let infere o tipo largo (string); const infere o literal ("Ana").
  • O retorno das funções é inferido; os parâmetros precisam de anotação.
  • Provocar um erro é um jeito de ver o tipo que o compilador deduziu.
