async/await e Promise<T>

Ler um arquivo, chamar uma API, esperar um tempo: tudo isso demora, e o JavaScript não fica parado esperando. Ele devolve uma Promise (uma “promessa” de valor futuro). O TypeScript tipa essa promessa como Promise<T>, onde T é o que vai chegar, e avisa quando você esquece de esperar por ela.

Você vai aprender
  • O tipo Promise<T> e funções async.
  • await, inclusive no topo do arquivo.
  • Promise.all para esperar várias coisas juntas.
  • Erros assíncronos com try/catch (e o e do tipo unknown).
  • O erro clássico: esquecer o await.

1. Uma função async

Vamos simular uma busca lenta com setTimeout:

function esperar(ms: number): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

async function buscarUsuario(id: number): Promise<string> {
  await esperar(100);
  return `usuario-${id}`;
}

console.log("antes");
const nome = await buscarUsuario(7);
console.log("chegou:", nome);
console.log("depois");
$ npx tsc && node dist/async.js
antes
chegou: usuario-7
depois
async function … : Promise<string>
uma função async sempre devolve uma Promise. O return de uma string vira Promise<string>.
await
pausa esta função até a Promise terminar e entrega o valor já “desembrulhado”: nome é string.
await no topo
em módulos (o nosso projeto é "type": "module"), dá para usar await fora de função.

2. Promise.all: várias de uma vez

Cada await em sequência espera o anterior. Quando as tarefas são independentes, Promise.all espera todas ao mesmo tempo, e o TypeScript sabe o tipo de cada posição:

const esperar = (ms: number) => new Promise<void>((r) => setTimeout(r, ms));

async function preco(produto: string): Promise<number> {
  await esperar(50);
  console.log("preço de", produto, "pronto");
  return produto.length * 10;
}

async function estoque(produto: string): Promise<boolean> {
  await esperar(20);
  console.log("estoque de", produto, "pronto");
  return true;
}

const [valor, temEstoque] = await Promise.all([preco("caneta"), estoque("caneta")]);
console.log(valor, temEstoque);
$ npx tsc && node dist/todas.js
estoque de caneta pronto
preço de caneta pronto
60 true

O estoque (20 ms) ficou pronto antes do preço (50 ms), mas o resultado vem na ordem da lista: valor é number e temEstoque é boolean.

3. Erros: try/catch e unknown

Se a Promise falha (um throw dentro da função async), o await lança o erro, e você o pega com try/catch. Mas o TypeScript não sabe o que foi lançado (qualquer coisa pode ser lançada), então e é unknown:

async function buscar(id: number): Promise<string> {
  if (id < 0) throw new Error("id inválido");
  return "ok";
}

try {
  await buscar(-1);
} catch (e) {
  console.log(e.message);
}
$ npx tsc
src/erro.ts(9,15): error TS18046: 'e' is of type 'unknown'.

A correção é conferir antes de usar (narrowing):

async function buscar(id: number): Promise<string> {
  if (id < 0) throw new Error("id inválido");
  return "ok";
}

try {
  await buscar(-1);
} catch (e) {
  if (e instanceof Error) {
    console.log("Falhou:", e.message);
  }
}
$ npx tsc && node dist/erro.js
Falhou: id inválido

Quando dá errado

Esquecer o await

Sem await, você tem a promessa, não o valor. O TypeScript percebe em vários lugares:

async function buscarNome(): Promise<string> {
  return "Ana";
}

const nome: string = buscarNome();
const tamanho = buscarNome().length;
if (buscarNome()) {
  console.log("achou");
}
$ npx tsc
src/sem-await.ts(5,7): error TS2322: Type 'Promise<string>' is not assignable to type 'string'.
src/sem-await.ts(6,30): error TS2339: Property 'length' does not exist on type 'Promise<string>'.
src/sem-await.ts(7,5): error TS2801: This condition will always return true since this 'Promise<string>' is always defined.

Os três erros têm a mesma pista: aparece Promise<string> onde você esperava uma string. O TS2801 ainda lembra que uma Promise sempre “existe”, então o if seria sempre verdadeiro. Em todos os casos a correção é await buscarNome().

Tipo de retorno sem Promise 
async function total(): number {
  return 42;
}
$ npx tsc
src/retorno.ts(1,25): error TS1064: The return type of an async function or method must be the global Promise<T> type. Did you mean to write 'Promise<number>'?

Função async sempre devolve Promise: escreva Promise<number>, como a própria mensagem sugere.

Missões

Missão: o código não compila porque falta esperar a Promise. Corrija para mostrar Resultado: 42.

async function dobroDepois(n: number): Promise<number> {
  return n * 2;
}
const r: number = dobroDepois(21);
console.log("Resultado: " + r);

async function dobroDepois(n: number): Promise<number> {
  return n * 2;
}
const r: number = await dobroDepois(21);
console.log("Resultado: " + r);

Resultado: 42

Missão: trate o erro com try/catch, conferindo e instanceof Error, e mostre Erro tratado: estoque vazio.

async function retirar(qtd: number): Promise<number> {
  if (qtd > 0) throw new Error("estoque vazio");
  return 0;
}
await retirar(1);

async function retirar(qtd: number): Promise<number> {
  if (qtd > 0) throw new Error("estoque vazio");
  return 0;
}
try {
  await retirar(1);
} catch (e) {
  if (e instanceof Error) {
    console.log("Erro tratado: " + e.message);
  }
}

Erro tratado: estoque vazio

Missão: use Promise.all para buscar os dois valores ao mesmo tempo e mostre Total: 30.

async function valorA(): Promise<number> { return 10; }
async function valorB(): Promise<number> { return 20; }
// busque os dois valores juntos aqui

async function valorA(): Promise<number> { return 10; }
async function valorB(): Promise<number> { return 20; }
const [a, b] = await Promise.all([valorA(), valorB()]);
console.log("Total: " + (a + b));

Total: 30

Resumo

  • Promise<T> é um T que chega depois; função async sempre devolve uma.
  • await desembrulha; funciona no topo dos módulos.
  • Promise.all espera várias juntas e mantém o tipo de cada posição.
  • No catch, e é unknown: confira com instanceof Error.
  • Esqueceu o await? O TypeScript costuma avisar.
