TypeScript direto no Node.js

Até aqui o caminho foi sempre npx tsc e depois node dist/arquivo.js. O Node 24 consegue rodar um .ts diretamente: ele apaga as anotações de tipo e executa o que sobra. É ótimo para scripts e para desenvolver rápido, mas tem regras. Vamos ver o que funciona, o que não funciona e como deixar o tsc de guarda.

Você vai aprender
  • node arquivo.ts e o que o Node faz com os tipos.
  • Por que o Node não confere tipos.
  • Sintaxe “apagável” e a opção erasableSyntaxOnly.
  • Imports com .ts e as opções que o tsc precisa.
  • Scripts no package.json para o dia a dia.

1. node arquivo.ts

type Pessoa = { nome: string; idade: number };

const p: Pessoa = { nome: "Ana", idade: 30 };
function apresentar(x: Pessoa): string {
  return `${x.nome} tem ${x.idade} anos`;
}
console.log(apresentar(p));
$ node --version
v24.22.1
$ node src/ola.ts
Ana tem 30 anos
$ ls
node_modules
package-lock.json
package.json
src
tsconfig.json

Rodou sem tsc e sem pasta dist. O Node trocou as anotações (: Pessoa, type Pessoa = …) por espaços e executou o JavaScript que sobrou.

2. O Node não confere tipos

const preco: number = "dez";
console.log("Preço:", preco);
$ node src/errado.ts
Preço: dez
$ npx tsc --noEmit
src/errado.ts(1,7): error TS2322: Type 'string' is not assignable to type 'number'.

O Node rodou um código com erro de tipo sem reclamar: ele apaga os tipos, não os confere. Quem confere continua sendo o tsc. Por isso o par do dia a dia é: node para rodar, npx tsc --noEmit para conferir.

3. Só sintaxe apagável

Algumas coisas do TypeScript geram código JavaScript (não dá para só apagar): enum, namespace com código e as propriedades de parâmetro do construtor (constructor(private nome: string)). O Node não aceita:

  Azul,
  Verde,
}
console.log(Cor.Verde);

A opção erasableSyntaxOnly do tsc avisa disso antes de rodar:

class Conta {
  constructor(private titular: string) {}
  mostrar() {
    return this.titular;
  }
}
console.log(new Conta("Ana").mostrar());
$ npx tsc --noEmit --erasableSyntaxOnly
src/conta.ts(2,15): error TS1294: This syntax is not allowed when 'erasableSyntaxOnly' is enabled.
src/enum.ts(1,6): error TS1294: This syntax is not allowed when 'erasableSyntaxOnly' is enabled.

As trocas: no lugar do enum, uma union de literais ou um objeto as const (aula de enums); no lugar da propriedade de parâmetro, um campo comum:

const Cor = { Azul: 0, Verde: 1 } as const;
type Cor = (typeof Cor)[keyof typeof Cor];

class Conta {
  titular: string;
  constructor(titular: string) {
    this.titular = titular;
  }
}

const c: Cor = Cor.Verde;
console.log(c, new Conta("Ana").titular);
$ node src/apagavel.ts
1 Ana
$ npx tsc --noEmit --erasableSyntaxOnly

4. Imports com .ts

Rodando direto, não existe dist/ nem .js: o import tem que apontar para o .ts de verdade.

export const dobro = (n: number): number => n * 2;
import { dobro } from "./util.ts";
console.log(dobro(21));
$ node src/main.ts
42
$ npx tsc
src/main.ts(1,23): error TS5097: An import path can only end with a '.ts' extension when 'allowImportingTsExtensions' is enabled.

O Node aceitou; o tsc, por padrão, não. Há duas opções para o tsc:

$ npx tsc --noEmit --allowImportingTsExtensions
$ npx tsc --rewriteRelativeImportExtensions && node dist/main.js
42
import { dobro } from "./util.js";
console.log(dobro(21));
//# sourceMappingURL=main.js.map
allowImportingTsExtensions
aceita .ts nos imports, mas só junto com noEmit (o tsc só confere; quem roda é o Node).
rewriteRelativeImportExtensions
aceita e, ao gerar o JS, reescreve ./util.ts para ./util.js. Serve para quem roda direto e também gera dist/.

5. Scripts no package.json

Para não decorar comandos, grave-os como scripts do npm:

const agora = "2026-11-21";
console.log("Rodando em", agora);
$ npm pkg set scripts.dev="node src/main.ts"
$ npm pkg set scripts.check="tsc --noEmit"
$ npm run dev

> projeto@1.0.0 dev
> node src/main.ts

Rodando em 2026-11-21
$ npm run check

> projeto@1.0.0 check
> tsc --noEmit

Dentro de scripts do npm, tsc funciona sem npx, porque o npm já procura em node_modules/.bin.

5. Qual destes o Node não consegue rodar direto?

Missões

As missões rodam direto com node src/missao.ts.

Missão: o Node não roda enum. Troque o enum Status por um objeto as const com os mesmos valores e mantenha a saída Status: 2.

enum Status {
  Novo = 1,
  Pago = 2,
}
console.log("Status: " + Status.Pago);

const Status = { Novo: 1, Pago: 2 } as const;
console.log("Status: " + Status.Pago);

Status: 2

Missão: crie src/taxas.ts abaixo e corrija o import de src/missao.ts para rodar com node. Saída esperada: Com taxa: 110.00.

Antes, crie também o arquivo src/taxas.ts:

export function comTaxa(valor: number): number {
  return valor * 1.1;
}
import { comTaxa } from "./taxas";
console.log("Com taxa: " + comTaxa(100).toFixed(2));

import { comTaxa } from "./taxas.ts";
console.log("Com taxa: " + comTaxa(100).toFixed(2));

Com taxa: 110.00

Resumo

  • O Node 24 roda .ts direto, apagando os tipos.
  • Ele não confere tipos: use npx tsc --noEmit.
  • Só sintaxe apagável: nada de enum ou propriedades de parâmetro (erasableSyntaxOnly avisa).
  • Imports com .ts; no tsc, allowImportingTsExtensions ou rewriteRelativeImportExtensions.
