Instalando o TypeScript

Nesta aula você monta o projeto que vai usar no guia inteiro: uma pasta com o TypeScript instalado e um arquivo de configuração, o tsconfig.json. São poucos comandos, e todos aparecem aqui com a resposta real do terminal.

Você vai aprender
  • A conferir se o Node e o npm estão instalados.
  • A criar o projeto com npm init -y e instalar o TypeScript com npm i -D typescript.
  • A rodar o compilador com npx tsc e ver a versão.
  • A criar o tsconfig.json com npx tsc --init e ajustar as pastas src e dist.

0. Antes de tudo: o Node

O TypeScript é instalado pelo npm, que vem junto com o Node.js. Se você ainda não tem o Node, instale a versão LTS pelo site oficial (nodejs.org) ou pelo gerenciador de pacotes do seu sistema. Depois confira:

$ node -v
v24.22.1
$ npm -v
11.21.1

Qualquer Node a partir da versão 20 serve para o guia. As saídas daqui foram colhidas com o Node 24.

1. Criar a pasta do projeto

Abra o terminal na sua pasta pessoal e crie a pasta projeto. O npm init -y cria o package.json, a “ficha” do projeto, aceitando as respostas padrão:

$ mkdir projeto
$ cd projeto
$ npm init -y
Wrote to /home/ana/projeto/package.json:

{
  "name": "projeto",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "",
  "license": "ISC",
  "type": "commonjs"
}

Como o guia usa a sintaxe moderna de módulos (import e export), mude o campo "type" para "module". O próprio npm faz isso, sem você abrir o arquivo:

$ npm pkg set type=module
$ npm pkg get type
"module"

2. Instalar o TypeScript

npm
o gerenciador de pacotes do Node
i
abreviação de install
-D
instala como dependência de desenvolvimento (só quem programa precisa do compilador)
typescript
o nome do pacote
$ npm i -D typescript

added 2 packages, and audited 3 packages in 659ms

found 0 vulnerabilities

O pacote fica na pasta node_modules, só deste projeto. Para rodar o compilador que está ali, use o npx, que procura o programa dentro do projeto:

$ npx tsc -v
Version 7.0.2
Por que não instalar “global”?

Daria para instalar com npm i -g typescript e rodar só tsc. Mas cada projeto pode precisar de uma versão diferente. Instalando no projeto, a versão fica anotada no package.json e quem baixar o seu código usa a mesma.

3. Criar o tsconfig.json

O tsconfig.json diz ao compilador como trabalhar: quão rigoroso ser, para qual versão de JavaScript gerar, onde ficam os arquivos. O --init cria um com valores recomendados:

$ npx tsc --init

Created a new tsconfig.json

You can learn more at https://aka.ms/tsconfig

Este é o arquivo criado (as linhas com // são comentários):

{
  // Visit https://aka.ms/tsconfig to read more about this file
  "compilerOptions": {
    // File Layout
    // "rootDir": "./src",
    // "outDir": "./dist",

    // Environment Settings
    // See also https://aka.ms/tsconfig/module
    "module": "nodenext",
    "target": "esnext",
    "types": [],
    // For nodejs:
    // "lib": ["esnext"],
    // "types": ["node"],
    // and npm install -D @types/node

    // Other Outputs
    "sourceMap": true,
    "declaration": true,
    "declarationMap": true,

    // Stricter Typechecking Options
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,

    // Style Options
    // "noImplicitReturns": true,
    // "noImplicitOverride": true,
    // "noUnusedLocals": true,
    // "noUnusedParameters": true,
    // "noFallthroughCasesInSwitch": true,
    // "noPropertyAccessFromIndexSignature": true,

    // Recommended Options
    "strict": true,
    "jsx": "react-jsx",
    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "noUncheckedSideEffectImports": true,
    "moduleDetection": "force",
    "skipLibCheck": true,
  }
}

Por enquanto, só uma coisa importa: o "strict": true, que liga o modo rigoroso. Ele é o que faz o TypeScript valer a pena, e fica ligado no guia inteiro. Os outros itens você conhece na aula O tsconfig.json.

4. Separar src e dist

Vamos guardar o código TypeScript em src/ e deixar o JavaScript gerado em dist/. No tsconfig.json, apague as duas barras do começo destas linhas, perto do topo:

    // "rootDir": "./src",
    // "outDir": "./dist",
    "rootDir": "./src",
    "outDir": "./dist",

Agora crie a pasta src e um primeiro arquivo para testar:

$ mkdir src
$ echo 'console.log("Projeto pronto!");' > src/teste.ts
$ npx tsc
$ node dist/teste.js
Projeto pronto!
$ ls dist
teste.d.ts
teste.d.ts.map
teste.js
teste.js.map

Funcionou: o tsc leu src/teste.ts e escreveu em dist/ o teste.js e mais três arquivos de apoio (o mapa .map e as declarações .d.ts, que você conhece na aula Arquivos de Declaração). Daqui em diante, toda aula usa este projeto.

Quando dá errado

Esquecer o npx

Sem o npx, o terminal procura um tsc instalado no sistema inteiro, e não acha:

$ tsc -v
bash: tsc: command not found

Use npx tsc dentro da pasta do projeto.

Rodar o tsc fora da pasta do projeto 
$ cd ..
$ npx tsc --noEmit

                                                                               
                This is not the tsc command you are looking for                
                                                                               

To get access to the TypeScript compiler, tsc, from the command line either:

- Use npm install typescript to first add TypeScript to your project before using npx
- Use yarn to avoid accidentally running code from un-installed packages

Na pasta pessoal não existe node_modules com o TypeScript. O npx então procurou no npm um pacote chamado tsc, baixou e rodou. Só que esse pacote não é o TypeScript: ele existe só para mostrar o aviso “This is not the tsc command you are looking for”. Volte com cd projeto e rode de novo lá dentro.

Passar o nome do arquivo para o tsc 
$ npx tsc src/ola.ts
error TS5112: tsconfig.json is present but will not be loaded if files are specified on commandline. Use '--ignoreConfig' to skip this error.

O TS5112 explica: com um tsconfig.json na pasta, passar arquivos na linha de comando faria o compilador ignorar a configuração, então ele se recusa. O jeito certo é rodar só npx tsc: ele compila tudo o que está em src/, com as configurações do projeto.

Resumo

  • O projeto do guia: npm init -y, npm pkg set type=module, npm i -D typescript, npx tsc --init.
  • No tsconfig.json, rootDir é ./src e outDir é ./dist.
  • Rotina: escrever em src/, rodar npx tsc, rodar node dist/….
  • Use sempre npx tsc dentro da pasta do projeto, sem nome de arquivo.
