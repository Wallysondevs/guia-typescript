Organizando o projeto

Com poucos arquivos, tudo cabe em src/. Quando o projeto cresce, uma boa organização faz você achar as coisas e evita imports confusos. Nesta aula montamos uma estrutura simples e comum, com scripts no package.json para compilar, rodar e conferir.

Você vai aprender
  • Separar o código em pastas por responsabilidade.
  • Arquivos index.ts que reexportam (“barris”).
  • Guardar tipos num lugar só e importá-los com import type.
  • Scripts build, start e check, e limpar o dist.
  • O que não vai para o git.

1. Uma estrutura simples

projeto/
├── package.json
├── tsconfig.json
├── src/
│   ├── index.ts            ← ponto de entrada
│   ├── tipos.ts            ← tipos compartilhados
│   ├── modelos/
│   │   ├── index.ts        ← reexporta a pasta
│   │   └── produto.ts
│   └── servicos/
│       ├── index.ts
│       └── estoque.ts
└── dist/                   ← gerado pelo tsc (não vai para o git)

Vamos criar os arquivos. Primeiro os tipos compartilhados:

export type Id = number;
export type Categoria = "papelaria" | "limpeza";
import type { Id, Categoria } from "../tipos.js";

export interface Produto {
  id: Id;
  nome: string;
  categoria: Categoria;
  quantidade: number;
}

export function criarProduto(id: Id, nome: string, categoria: Categoria): Produto {
  return { id, nome, categoria, quantidade: 0 };
}
export * from "./produto.js";
import type { Produto } from "../modelos/index.js";

export function repor(p: Produto, qtd: number): Produto {
  return { ...p, quantidade: p.quantidade + qtd };
}

export function emFalta(lista: Produto[]): string[] {
  return lista.filter((p) => p.quantidade === 0).map((p) => p.nome);
}
export * from "./estoque.js";
import { criarProduto } from "./modelos/index.js";
import { repor, emFalta } from "./servicos/index.js";

const lapis = repor(criarProduto(1, "Lápis", "papelaria"), 30);
const sabao = criarProduto(2, "Sabão", "limpeza");

console.log(lapis);
console.log("Em falta:", emFalta([lapis, sabao]));

O dist/ repete as pastas do src/. Repare nos imports do index.ts: "./modelos/index.js" em vez de "./modelos/produto.js". Se amanhã a pasta modelos ganhar mais arquivos, quem importa não muda.

Barril, só com moderação

Os index.ts que reexportam são práticos, mas um barril gigante, com o projeto inteiro, deixa difícil saber de onde vem cada coisa. Um por pasta costuma bastar.

2. Scripts: build, start e check

$ npm pkg set scripts.build="tsc"
$ npm pkg set scripts.start="node dist/index.js"
$ npm pkg set scripts.check="tsc --noEmit"
$ npm pkg get scripts
{
  "test": "echo \"Error: no test specified\" && exit 1",
  "build": "tsc",
  "start": "node dist/index.js",
  "check": "tsc --noEmit"
}
$ npm run build

> projeto@1.0.0 build
> tsc
$ npm start

> projeto@1.0.0 start
> node dist/index.js

{ id: 1, nome: 'Lápis', categoria: 'papelaria', quantidade: 30 }
Em falta: [ 'Sabão' ]
npm run build
compila src/ para dist/.
npm start
roda o programa compilado (start dispensa o run).
npm run check
confere os tipos sem gerar nada.

3. Arquivos órfãos no dist

O tsc cria e atualiza arquivos em dist/, mas não apaga. Se você renomear ou apagar um .ts, o .js antigo continua lá:

$ rm src/servicos/estoque.ts
$ npx tsc
src/index.ts(2,10): error TS2305: Module '"./servicos/index.js"' has no exported member 'repor'.
src/index.ts(2,17): error TS2305: Module '"./servicos/index.js"' has no exported member 'emFalta'.
src/servicos/index.ts(1,15): error TS2307: Cannot find module './estoque.js' or its corresponding type declarations.
$ ls dist/servicos
estoque.d.ts
estoque.d.ts.map
estoque.js
estoque.js.map
index.d.ts
index.d.ts.map
index.js
index.js.map

O tsc reclamou do import quebrado, mas o estoque.js antigo ficou em dist/servicos, e o programa ainda rodaria com o código velho. Por isso é comum limpar antes de compilar:

$ npm pkg set scripts.build="rm -rf dist && tsc"
$ npm pkg get scripts.build
"rm -rf dist && tsc"

(rm -rf é do Linux e do macOS. No Windows, use node -e "require('fs').rmSync('dist',{recursive:true,force:true})" && tsc, que funciona em todos.)

4. O que não vai para o git

node_modules (é baixado com npm install) e dist (é gerado com npm run build) não devem ir para o repositório. Crie um .gitignore:

node_modules/
dist/
$ git init -q
$ npx tsc
$ git status --short --untracked-files=all
?? .gitignore
?? package-lock.json
?? package.json
?? src/index.ts
?? tsconfig.json

O git só enxerga o que importa: o código-fonte e as configurações.

Quando dá errado

Arquivo fora do rootDir

Todo arquivo .ts do projeto precisa ficar dentro de src/ (o rootDir). Um arquivo solto na raiz quebra a compilação:

console.log("ok");
export const porta = 3000;
$ npx tsc
error TS6059: File '/home/ana/projeto/config.ts' is not under 'rootDir' '/home/ana/projeto/src'. 'rootDir' is expected to contain all source files.
  The file is in the program because:
    Matched by default include pattern '**/*'
  File is ECMAScript module because '/home/ana/projeto/package.json' has field "type" with value "module"

Mova o arquivo para src/ (por exemplo, src/config.ts).

Missões

Missão: crie os dois arquivos abaixo e, em src/missao.ts, importe novoCliente pelo barril "./modelos/index.js". Saída esperada: Ana: 0 pontos.

Antes, crie também o arquivo src/modelos/cliente.ts:

export interface Cliente {
  nome: string;
  pontos: number;
}
export function novoCliente(nome: string): Cliente {
  return { nome, pontos: 0 };
}

Antes, crie também o arquivo src/modelos/index.ts:

export * from "./cliente.js";
const c = { nome: "Ana", pontos: 0 };
console.log(`${c.nome}: ${c.pontos} pontos`);

import { novoCliente } from "./modelos/index.js";
const c = novoCliente("Ana");
console.log(`${c.nome}: ${c.pontos} pontos`);

Ana: 0 pontos

Missão: crie src/tipos.ts abaixo e, em src/missao.ts, importe o tipo Preco com import type para tipar p. Saída esperada: BRL 9.90.

Antes, crie também o arquivo src/tipos.ts:

export type Moeda = "BRL" | "USD";
export interface Preco {
  valor: number;
  moeda: Moeda;
}
const p = { valor: 9.9, moeda: "BRL" };
console.log(`${p.moeda} ${p.valor.toFixed(2)}`);

import type { Preco } from "./tipos.js";
const p: Preco = { valor: 9.9, moeda: "BRL" };
console.log(`${p.moeda} ${p.valor.toFixed(2)}`);

BRL 9.90

Resumo

  • Pastas por responsabilidade, com um index.ts que reexporta.
  • Tipos compartilhados num arquivo, importados com import type.
  • Scripts build, start e check; limpe o dist antes de compilar.
  • node_modules/ e dist/ ficam fora do git.
