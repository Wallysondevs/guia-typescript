Tipos de pacotes npm

Boa parte do seu código vai usar pacotes do npm. Alguns já vêm com tipos (trazem os próprios arquivos .d.ts). Outros foram escritos em JavaScript puro, e os tipos ficam num pacote separado, mantido pela comunidade no projeto DefinitelyTyped, com nome @types/nome-do-pacote. Nesta aula você instala os dois casos de verdade.

Você vai aprender
  • O erro TS7016 e como resolvê-lo com @types.
  • Instalar tipos como devDependencies.
  • Usar módulos do Node (node:fs, process) com @types/node.
  • A opção types do tsconfig.json.

1. Um pacote sem tipos: lodash

O lodash é uma biblioteca famosa de utilidades, escrita em JavaScript. Instale e use:

$ npm i lodash

added 1 package, and audited 4 packages in 365ms

found 0 vulnerabilities
import _ from "lodash";
console.log(_.chunk([1, 2, 3, 4, 5], 2));
$ npx tsc
src/lodash.ts(1,15): error TS7016: Could not find a declaration file for module 'lodash'. '/home/ana/projeto/node_modules/lodash/lodash.js' implicitly has an 'any' type.
  Try `npm i --save-dev @types/lodash` if it exists or add a new declaration (.d.ts) file containing `declare module 'lodash';`

O TS7016 diz: o pacote existe, mas não tem arquivo de declaração, então tudo nele seria any. A própria mensagem sugere o caminho:

$ npm i -D @types/lodash

added 1 package, and audited 5 packages in 327ms

found 0 vulnerabilities
$ npx tsc && node dist/lodash.js
[ [ 1, 2 ], [ 3, 4 ], [ 5 ] ]
npm i lodash
o código do pacote: vai em dependencies, porque o programa precisa dele rodando.
npm i -D @types/lodash
só os tipos: vão em devDependencies (-D), porque só o compilador usa.
$ npm pkg get dependencies devDependencies
{
  "dependencies": {
    "lodash": "^4.18.1"
  },
  "devDependencies": {
    "@types/lodash": "^4.17.27",
    "typescript": "^7.0.2"
  }
}

2. Agora o TypeScript conhece o lodash

import _ from "lodash";

const grupos: string[] = _.chunk([1, 2, 3], 2);
console.log(_.capitalize(123));
$ npx tsc
src/lodash.ts(3,7): error TS2322: Type 'number[][]' is not assignable to type 'string[]'.
  Type 'number[]' is not assignable to type 'string'.
src/lodash.ts(4,26): error TS2345: Argument of type 'number' is not assignable to parameter of type 'string'.

Com os tipos, o compilador sabe que _.chunk devolve number[][] e que _.capitalize espera texto.

3. Os módulos do Node: @types/node

Ler arquivos, ver a versão do Node, ler variáveis de ambiente: tudo isso vem do Node, e os tipos dele também ficam num pacote @types:

import { readFileSync } from "node:fs";

const pacote = JSON.parse(readFileSync("package.json", "utf8"));
console.log(pacote.name, process.version);
$ npx tsc
src/node.ts(1,30): error TS2591: Cannot find name 'node:fs'. Do you need to install type definitions for node? Try `npm i --save-dev @types/node` and then add 'node' to the types field in your tsconfig.
src/node.ts(4,26): error TS2591: Cannot find name 'process'. Do you need to install type definitions for node? Try `npm i --save-dev @types/node` and then add 'node' to the types field in your tsconfig.

A mensagem pede duas coisas. Primeiro, instalar os tipos. Use a versão que combina com o seu Node (aqui, a 24):

$ npm i -D @types/node@24

added 2 packages, and audited 5 packages in 422ms

found 0 vulnerabilities
$ npx tsc
src/node.ts(1,30): error TS2591: Cannot find name 'node:fs'. Do you need to install type definitions for node? Try `npm i --save-dev @types/node` and then add 'node' to the types field in your tsconfig.
src/node.ts(4,26): error TS2591: Cannot find name 'process'. Do you need to install type definitions for node? Try `npm i --save-dev @types/node` and then add 'node' to the types field in your tsconfig.

Instalado, mas o erro continua. É a segunda parte da mensagem: o tsconfig.json do projeto tem "types": [], que quer dizer “não carregue nenhum @types global automaticamente”. O próprio arquivo, logo abaixo, traz a dica comentada // "types": ["node"],. Troque a linha para:

    "types": ["node"],
$ npx tsc && node dist/node.js
projeto v24.22.1
Por que o lodash não precisou disso?

A opção types só controla os tipos globais (como process) e módulos que você não importa por nome de pacote. Pacotes que você importa (import _ from "lodash") acham o seu @types sozinhos.

4. Como saber se um pacote já traz tipos

Olhe o package.json do pacote: se tiver o campo types (ou typings), os tipos vêm junto e não é preciso @types. Compare o lodash com o dayjs (outra biblioteca popular, de datas):

$ npm view lodash types
$ npm view dayjs types
index.d.ts
$ npm view @types/lodash version
4.17.27

O npm view lodash types não mostrou nada: o lodash não traz tipos (por isso existe @types/lodash). Já o dayjs aponta para o seu arquivo de declaração (index.d.ts): basta instalar e usar. Alguns pacotes modernos declaram os tipos no campo exports em vez de types; na dúvida, instale e veja se o tsc reclama. Na página do pacote no site do npm, um selo “TS” azul indica tipos incluídos; um selo “DT” indica que existem tipos no DefinitelyTyped.

Quando dá errado

Tipos instalados como dependência comum, ou esquecidos no outro computador

Tipos funcionam com npm i @types/x sem -D, mas aí vão para dependencies à toa. E se o colega clonar o projeto e rodar só npx tsc sem npm install, verá de novo TS7016 ou TS2307. A regra: tudo o que o projeto usa precisa estar no package.json, e quem clona roda npm install antes.

Pacote sem tipos e sem @types

Se não existir @types/x, a mensagem do TS7016 mostra a saída de emergência: criar um arquivo .d.ts com declare module 'x';. Isso tira o erro, mas deixa tudo como any. Melhor é escrever as declarações de verdade, como você vê na aula de arquivos de declaração.

Missões

As missões abaixo usam o projeto desta aula, já com lodash, @types/lodash, @types/node@24 e "types": ["node"].

Missão: corrija o tipo de total (o _.sum devolve número) para compilar e mostrar Total: 60.

import _ from "lodash";
const total: string = _.sum([10, 20, 30]);
console.log("Total: " + total);

import _ from "lodash";
const total: number = _.sum([10, 20, 30]);
console.log("Total: " + total);

Total: 60

Missão: importe readFileSync de "node:fs", leia o package.json e mostre Projeto: projeto (o campo name).

const pacote = { name: "?" };
console.log("Projeto: " + pacote.name);

import { readFileSync } from "node:fs";
const pacote = JSON.parse(readFileSync("package.json", "utf8"));
console.log("Projeto: " + pacote.name);

Projeto: projeto

Resumo

  • Pacote em JavaScript puro → npm i -D @types/pacote.
  • Pacote com tipos próprios (campo types) → nada a instalar.
  • Node: npm i -D @types/node@24 e "types": ["node"].
  • TS7016: faltam tipos do pacote; TS2591: faltam os do Node.
