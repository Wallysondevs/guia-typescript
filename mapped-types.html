Mapped Types

Lembra do Partial e do Readonly? Eles não são mágica: são mapped types, tipos que “passeiam” pelas chaves de outro tipo e montam um novo, campo a campo. Nesta aula você aprende a escrever os seus.

Você vai aprender
  • A sintaxe { [K in Chaves]: Tipo }.
  • Percorrer as chaves de um tipo com keyof.
  • Colocar e tirar readonly e ? (com + e -).
  • Renomear chaves com as.

1. A forma básica

Um mapped type percorre uma união de chaves e dá um tipo para cada uma:

type Dia = "seg" | "ter" | "qua";
type Agenda = { [D in Dia]: string[] };

const semana: Agenda = {
  seg: ["academia"],
  ter: [],
  qua: ["reunião", "dentista"],
};
console.log(semana);

const incompleta: Agenda = { seg: [], ter: [] };
$ npx tsc
src/mapa.ts(11,7): error TS2741: Property 'qua' is missing in type '{ seg: never[]; ter: never[]; }' but required in type 'Agenda'.
[D in Dia]
para cada D da união Dia ("seg", "ter", "qua")…
: string[]
…crie a propriedade D com este tipo.

O resultado é igual a escrever { seg: string[]; ter: string[]; qua: string[] }, e por isso faltar qua dá erro.

2. Percorrendo outro tipo com keyof

O uso mais comum: [K in keyof T] percorre os campos de T, e T[K] é o tipo de cada um.

type Produto = { nome: string; preco: number; ativo: boolean };

type Validacao<T> = { [K in keyof T]: boolean };
type ComoTexto<T> = { [K in keyof T]: string };
type Getters<T> = { [K in keyof T]: () => T[K] };

const v: Validacao<Produto> = { nome: true, preco: false, ativo: true };
const form: ComoTexto<Produto> = { nome: "Caneta", preco: "2.5", ativo: "sim" };
const g: Getters<Produto> = {
  nome: () => "Caneta",
  preco: () => 2.5,
  ativo: () => true,
};
console.log(v, form, g.preco());

const errado: Getters<Produto> = { nome: () => "x", preco: () => "caro", ativo: () => true };
$ npx tsc
src/keyof.ts(16,66): error TS2322: Type 'string' is not assignable to type 'number'.

Em Getters, a função de preco precisa devolver Produto["preco"], ou seja, number.

3. Modificadores: readonly, ? e o sinal de menos

Dá para pôr readonly e ? em todos os campos, e também tirar com -. É assim que Partial, Readonly e Required são escritos:

type MeuPartial<T> = { [K in keyof T]?: T[K] };
type MeuReadonly<T> = { readonly [K in keyof T]: T[K] };
type MeuRequired<T> = { [K in keyof T]-?: T[K] };
type Mutavel<T> = { -readonly [K in keyof T]: T[K] };

type Config = { readonly tema: string; fonte?: number };

const parcial: MeuPartial<Config> = {};
const fixa: MeuReadonly<{ x: number }> = { x: 1 };
const completa: MeuRequired<Config> = { tema: "claro" };
const livre: Mutavel<Config> = { tema: "claro" };
livre.tema = "escuro";
fixa.x = 2;
console.log(parcial, completa, livre);
$ npx tsc
src/modificadores.ts(10,7): error TS2741: Property 'fonte' is missing in type '{ tema: string; }' but required in type 'MeuRequired<Config>'.
src/modificadores.ts(13,6): error TS2540: Cannot assign to 'x' because it is a read-only property.
  • -? tirou o opcional de fonte: por isso completa dá erro.
  • -readonly liberou livre.tema = "escuro".
  • readonly bloqueou fixa.x = 2.

4. Renomeando chaves com as

Com as você muda o nome de cada chave. Junto com os template literal types (próximas aulas), dá para gerar nomes como getNome:

type Pessoa = { nome: string; idade: number };

type ComPrefixo<T> = { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] };
type SemIdade<T> = { [K in keyof T as K extends "idade" ? never : K]: T[K] };

const p: ComPrefixo<Pessoa> = {
  getNome: () => "Ana",
  getIdade: () => 30,
};
const s: SemIdade<Pessoa> = { nome: "Duda" };
console.log(p.getNome(), p.getIdade(), s);

const errado: ComPrefixo<Pessoa> = { nome: () => "Ana", getIdade: () => 30 };
$ npx tsc
src/renomear.ts(13,38): error TS2353: Object literal may only specify known properties, and 'nome' does not exist in type 'ComPrefixo<Pessoa>'.

Mapear uma chave para never com as remove a chave: foi assim que SemIdade funcionou (é o mesmo truque do Omit).

Quando dá errado

Usar in fora de um mapped type

A sintaxe [K in …] só existe dentro de um type. Numa interface, não:

type Dia = "seg" | "ter";
interface Agenda {
  [D in Dia]: string[];
}
$ npx tsc
src/interface.ts(3,3): error TS7061: A mapped type may not declare properties or methods.

Use type Agenda = { [D in Dia]: string[] }.

Referência rápida

EscritaEfeito
{ [K in U]: X }uma propriedade para cada membro de U
{ [K in keyof T]: T[K] }copia os campos de T
readonly [K in …] / -readonlypõe / tira readonly
[K in …]? / -?põe / tira o opcional
[K in keyof T as NovoNome]renomeia (ou remove com never)

Missões

Missão: crie o tipo Preferencias como mapped type sobre Canal, com cada canal sendo boolean. Saída esperada: { email: true, sms: false, push: true }.

type Canal = "email" | "sms" | "push";
type Preferencias = { email: boolean; sms: boolean; push: boolean };
const p: Preferencias = { email: true, sms: false, push: true };
console.log(p);

type Canal = "email" | "sms" | "push";
type Preferencias = { [C in Canal]: boolean };
const p: Preferencias = { email: true, sms: false, push: true };
console.log(p);

{ email: true, sms: false, push: true }

Missão: escreva o mapped type Anulavel<T>, em que cada campo de T também aceita null (T[K] | null). Saída esperada: { nome: 'Ana', email: null }.

type Contato = { nome: string; email: string };
type Anulavel<T> = T;
const c: Anulavel<Contato> = { nome: "Ana", email: null };
console.log(c);

type Contato = { nome: string; email: string };
type Anulavel<T> = { [K in keyof T]: T[K] | null };
const c: Anulavel<Contato> = { nome: "Ana", email: null };
console.log(c);

{ nome: 'Ana', email: null }

Resumo

  • Mapped type: { [K in Chaves]: Tipo }, um campo por chave.
  • [K in keyof T] com T[K] transforma os campos de outro tipo.
  • readonly, ?, -readonly e -? mudam os modificadores.
  • as renomeia chaves; as never remove.
