Objetos e type

Quase todo programa lida com objetos: um usuário, um produto, um pedido. Em TypeScript você descreve a forma do objeto (quais campos, de quais tipos) e pode dar um nome a essa forma com type.

Você vai aprender
  • A escrever o tipo de um objeto: { nome: string; idade: number }.
  • A dar nome ao tipo com type Usuario = { … }.
  • Propriedades opcionais (?) e somente leitura (readonly).
  • Os erros de campo que falta, que sobra ou que não existe.

1. O tipo de um objeto

const livro: { titulo: string; paginas: number } = {
  titulo: "Dom Casmurro",
  paginas: 256,
};

console.log(livro.titulo, "-", livro.paginas, "páginas");
$ npx tsc && node dist/objeto.js
Dom Casmurro - 256 páginas

Escrever a forma inteira toda vez cansa. Para isso existe o type.

2. Dando nome com type

type
cria um apelido (alias) para um tipo
Produto
o nome do tipo, por costume com inicial maiúscula
= { nome: string; preco: number }
a forma que o nome representa
type Produto = {
  nome: string;
  preco: number;
  emEstoque: boolean;
};

const cafe: Produto = { nome: "Café", preco: 18.9, emEstoque: true };
const cha: Produto = { nome: "Chá", preco: 9.5, emEstoque: false };

function etiqueta(p: Produto): string {
  const situacao = p.emEstoque ? "disponível" : "esgotado";
  return `${p.nome}: R$ ${p.preco.toFixed(2)} (${situacao})`;
}

console.log(etiqueta(cafe));
console.log(etiqueta(cha));
$ npx tsc && node dist/produto.js
Café: R$ 18.90 (disponível)
Chá: R$ 9.50 (esgotado)

O type não serve só para objetos: type Id = number; e type Operacao = (a: number, b: number) => number; também valem.

3. Campo que falta, que sobra ou que não existe

type Produto = { nome: string; preco: number };

const a: Produto = { nome: "Pão" };
const b: Produto = { nome: "Leite", preco: 5, marca: "Boa" };
const c: Produto = { nome: "Ovo", preco: 1 };
console.log(c.peso);
$ npx tsc
src/campos.ts(3,7): error TS2741: Property 'preco' is missing in type '{ nome: string; }' but required in type 'Produto'.
src/campos.ts(4,47): error TS2353: Object literal may only specify known properties, and 'marca' does not exist in type 'Produto'.
src/campos.ts(6,15): error TS2339: Property 'peso' does not exist on type 'Produto'.

Três erros diferentes: TS2741 (falta o preco), TS2353 (o marca não faz parte do tipo) e TS2339 (ler um campo que o tipo não tem).

4. Opcionais e readonly

type Usuario = {
  readonly id: number;
  nome: string;
  email?: string;
};

const u: Usuario = { id: 1, nome: "Ana" };
u.nome = "Ana Souza";
console.log(u);
console.log(u.email ?? "sem e-mail");
$ npx tsc && node dist/opcionais.js
{ id: 1, nome: 'Ana Souza' }
sem e-mail

O email? pode faltar. E o readonly id não pode ser alterado depois de criado:

type Usuario = { readonly id: number; nome: string };
const u: Usuario = { id: 1, nome: "Ana" };
u.id = 2;
$ npx tsc
src/readonly.ts(3,3): error TS2540: Cannot assign to 'id' because it is a read-only property.

5. Objetos dentro de objetos

type Endereco = { rua: string; cidade: string };
type Cliente = { nome: string; endereco: Endereco; telefones: string[] };

const cliente: Cliente = {
  nome: "Caio",
  endereco: { rua: "Rua das Flores, 10", cidade: "Natal" },
  telefones: ["84 99999-0000"],
};

console.log(`${cliente.nome} mora em ${cliente.endereco.cidade}`);
console.log(cliente.telefones.length, "telefone(s)");
$ npx tsc && node dist/aninhado.js
Caio mora em Natal
1 telefone(s)

Quando dá errado

Erro de digitação no nome do campo 
type Produto = { nome: string; preco: number };
const p: Produto = { nome: "Café", prceo: 10 };
$ npx tsc
src/digitacao.ts(2,36): error TS2561: Object literal may only specify known properties, but 'prceo' does not exist in type 'Produto'. Did you mean to write 'preco'?

O compilador percebe o erro e ainda sugere o nome certo.

Usar o type antes de criar… não é problema

Os tipos não existem quando o programa roda, então a ordem não importa para eles: dá para usar um type declarado mais abaixo no arquivo. O que importa é que o nome exista em algum lugar do arquivo (ou seja importado).

Missões

Missão: crie type Filme = { titulo: string; ano: number }, um filme "Central do Brasil" de 1998 e mostre Central do Brasil (1998).

const filme = { titulo: "Central do Brasil", ano: 1998 };

type Filme = { titulo: string; ano: number };
const filme: Filme = { titulo: "Central do Brasil", ano: 1998 };
console.log(`${filme.titulo} (${filme.ano})`);

Central do Brasil (1998)

Missão: no tipo Contato, torne o telefone opcional, para o contato da Bia (sem telefone) ser aceito. A função já mostra sem telefone quando ele falta.

type Contato = { nome: string; telefone: string };

function mostrar(c: Contato) {
  console.log(`${c.nome} - ${c.telefone ?? "sem telefone"}`);
}
mostrar({ nome: "Bia" });
mostrar({ nome: "Caio", telefone: "81 98888-7777" });

type Contato = { nome: string; telefone?: string };

function mostrar(c: Contato) {
  console.log(`${c.nome} - ${c.telefone ?? "sem telefone"}`);
}
mostrar({ nome: "Bia" });
mostrar({ nome: "Caio", telefone: "81 98888-7777" });

Bia - sem telefone
Caio - 81 98888-7777

Missão: marque o codigo do tipo Pedido como readonly e cole o erro que aparece quando o código tenta mudá-lo.

type Pedido = { codigo: string; total: number };
const p: Pedido = { codigo: "A1", total: 50 };
p.codigo = "B2";
console.log(p);

type Pedido = { readonly codigo: string; total: number };
const p: Pedido = { codigo: "A1", total: 50 };
p.codigo = "B2";
console.log(p);

src/missao.ts(3,3): error TS2540: Cannot assign to 'codigo' because it is a read-only property.

Resumo

  • O tipo de um objeto lista os campos e os tipos deles.
  • type Nome = … dá nome a um tipo para reutilizar.
  • ? marca campo opcional; readonly, campo que não muda.
  • Campo faltando (TS2741), sobrando (TS2353) ou inexistente (TS2339) viram erro.
