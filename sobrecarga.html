Sobrecarga de funções

Algumas funções aceitam entradas diferentes e devolvem coisas diferentes conforme a entrada. Uma union no parâmetro e no retorno perde essa ligação (“se entrar texto, sai texto”). Com sobrecargas (overloads), você escreve várias assinaturas para a mesma função, e o TypeScript escolhe a certa a cada chamada.

Você vai aprender
  • Escrever assinaturas de sobrecarga e a implementação.
  • Por que a implementação não pode ser chamada diretamente.
  • A ordem das sobrecargas.
  • Quando uma union simples é melhor.

1. O problema com union

function inverter(v: string | number[]): string | number[] {
  return typeof v === "string" ? v.split("").reverse().join("") : [...v].reverse();
}

const t = inverter("abc");
console.log(t.toUpperCase());
$ npx tsc
src/union.ts(6,15): error TS2339: Property 'toUpperCase' does not exist on type 'string | number[]'.
  Property 'toUpperCase' does not exist on type 'number[]'.

Você passou texto e sabe que volta texto, mas o tipo de retorno é a union inteira.

2. Assinaturas de sobrecarga

function inverter(v: string): string;
function inverter(v: number[]): number[];
function inverter(v: string | number[]): string | number[] {
  return typeof v === "string" ? v.split("").reverse().join("") : [...v].reverse();
}

const t = inverter("abc");
const n = inverter([1, 2, 3]);
console.log(t.toUpperCase(), n.map((x) => x * 10));
$ npx tsc && node dist/sobrecarga.js
CBA [ 30, 20, 10 ]
as duas primeiras linhas
as assinaturas que quem chama enxerga: texto → texto; lista → lista. Sem corpo, terminadas em ;.
a terceira
a implementação: tem o corpo e precisa aceitar todos os casos. Ela não aparece para quem chama.

3. Só as sobrecargas valem para quem chama

function inverter(v: string): string;
function inverter(v: number[]): number[];
function inverter(v: string | number[]): string | number[] {
  return typeof v === "string" ? v.split("").reverse().join("") : [...v].reverse();
}

const talvez: string | number[] = Math.random() > 2 ? "x" : [1];
inverter(talvez);
inverter(true);
$ npx tsc
src/chamadas.ts(8,10): error TS2769: No overload matches this call.
  The last overload gave the following error.
    Argument of type 'string | number[]' is not assignable to parameter of type 'number[]'.
      Type 'string' is not assignable to type 'number[]'.
src/chamadas.ts(9,10): error TS2769: No overload matches this call.
  The last overload gave the following error.
    Argument of type 'boolean' is not assignable to parameter of type 'number[]'.

Mesmo que a implementação aceite string | number[], nenhuma sobrecarga aceita a union, então a chamada é recusada. Se você quer permitir, adicione uma terceira sobrecarga function inverter(v: string | number[]): string | number[];.

4. Sobrecarga em métodos e a ordem

As sobrecargas são testadas de cima para baixo, e vale a primeira que servir. Coloque as mais específicas primeiro:

class Formatador {
  formatar(v: Date): string;
  formatar(v: number, casas?: number): string;
  formatar(v: Date | number, casas = 2): string {
    if (v instanceof Date) return v.toISOString().slice(0, 10);
    return v.toFixed(casas);
  }
}

const f = new Formatador();
console.log(f.formatar(new Date("2026-11-21T12:00:00Z")));
console.log(f.formatar(3.14159));
console.log(f.formatar(3.14159, 4));
$ npx tsc && node dist/metodo.js
2026-11-21
3.14
3.1416

Quando dá errado

Implementação que não cobre uma sobrecarga 
function dobro(v: string): string;
function dobro(v: number): number;
function dobro(v: number): number {
  return v * 2;
}
$ npx tsc
src/incompativel.ts(1,10): error TS2394: This overload signature is not compatible with its implementation signature.

A implementação precisa aceitar todos os tipos das sobrecargas: aqui, v: string | number.

Union ou sobrecarga?

Se o retorno não depende do tipo da entrada (ex.: tamanho(v: string | unknown[]): number), prefira uma union simples. Sobrecarga é para quando a entrada decide o tipo da saída.

Missão: adicione duas sobrecargas a primeiro: (v: string): string e (v: number[]): number, para que o código compile. Saída esperada: A 10.

function primeiro(v: string | number[]): string | number {

}
const letra = primeiro("Ana");
const num = primeiro([5, 7]);
console.log(letra.toUpperCase(), num * 2);

Missão: a implementação de dobro não cobre a sobrecarga de texto. Corrija a implementação (parâmetro string | number; texto se repete com .repeat(2)). Saída esperada: abcabc 8.

function dobro(v: string): string;
function dobro(v: number): number;
function dobro(v: number): number {
  return v * 2;
}
console.log(dobro("abc"), dobro(4));

function dobro(v: string): string;
function dobro(v: number): number;
function dobro(v: string | number): string | number {
  return typeof v === "string" ? v.repeat(2) : v * 2;
}
console.log(dobro("abc"), dobro(4));

abcabc 8

Resumo

  • Sobrecargas ligam o tipo da entrada ao tipo da saída.
  • Assinaturas sem corpo em cima; uma implementação que cobre todas embaixo.
  • Quem chama só vê as sobrecargas, testadas de cima para baixo.
  • Se o retorno não muda com a entrada, use union.
