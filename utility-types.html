Utility Types

O TypeScript vem com uma caixa de ferramentas de tipos prontos, os utility types. Eles criam um tipo novo a partir de outro: “o mesmo, mas com tudo opcional”, “só estes campos”, “todos menos este”. Com eles você evita repetir a mesma forma várias vezes.

Você vai aprender
  • Partial, Required e Readonly.
  • Pick e Omit.
  • Record.
  • Para unions e funções: Exclude, Extract, NonNullable, ReturnType e Parameters.

Todos os exemplos usam este tipo como base:

type Usuario = {
  id: number;
  nome: string;
  email: string;
  idade?: number;
};

1. Partial: tudo opcional

Ótimo para funções de atualização, que recebem só o que mudou:

type Usuario = { id: number; nome: string; email: string; idade?: number };

function atualizar(u: Usuario, mudancas: Partial<Usuario>): Usuario {
  return { ...u, ...mudancas };
}

const ana: Usuario = { id: 1, nome: "Ana", email: "ana@exemplo.com" };
console.log(atualizar(ana, { email: "ana.souza@exemplo.com" }));
console.log(atualizar(ana, { idade: 31, nome: "Ana Souza" }));
$ npx tsc && node dist/partial.js
{ id: 1, nome: 'Ana', email: 'ana.souza@exemplo.com' }
{ id: 1, nome: 'Ana Souza', email: 'ana@exemplo.com', idade: 31 }

2. Required e Readonly

type Usuario = { id: number; nome: string; email: string; idade?: number };

const completo: Required<Usuario> = { id: 2, nome: "Duda", email: "duda@exemplo.com" };

const fixo: Readonly<Usuario> = { id: 3, nome: "Caio", email: "caio@exemplo.com" };
fixo.nome = "Outro";
$ npx tsc
src/required.ts(3,7): error TS2741: Property 'idade' is missing in type '{ id: number; nome: string; email: string; }' but required in type 'Required<Usuario>'.
src/required.ts(6,6): error TS2540: Cannot assign to 'nome' because it is a read-only property.

Required tirou o ? da idade, que passou a ser obrigatória. Readonly pôs readonly em todos os campos.

3. Pick e Omit: escolher ou tirar campos

type Usuario = { id: number; nome: string; email: string; idade?: number };

type Cartao = Pick<Usuario, "nome" | "email">;
type NovoUsuario = Omit<Usuario, "id">;

const c: Cartao = { nome: "Ana", email: "ana@exemplo.com" };

function cadastrar(dados: NovoUsuario): Usuario {
  return { id: 7, ...dados };
}

console.log(c);
console.log(cadastrar({ nome: "Duda", email: "duda@exemplo.com" }));

const errado: Cartao = { nome: "Caio", email: "c@exemplo.com", id: 9 };
$ npx tsc
src/pick-omit.ts(15,64): error TS2353: Object literal may only specify known properties, and 'id' does not exist in type 'Cartao'.

O Cartao tem só nome e email, então o id sobrando é recusado. O NovoUsuario é tudo menos id: perfeito para um cadastro, em que o id ainda não existe.

4. Record: um objeto de chaves e valores

type Dia = "seg" | "ter" | "qua";

const horas: Record<Dia, number> = { seg: 8, ter: 6, qua: 7 };
const precos: Record<string, number> = { cafe: 5, pao: 1.5 };

let total = 0;
for (const d of Object.keys(horas) as Dia[]) total += horas[d];
console.log("horas na semana:", total);
console.log(precos["cafe"]);

const faltando: Record<Dia, number> = { seg: 8, ter: 6 };
$ npx tsc
src/record.ts(11,7): error TS2741: Property 'qua' is missing in type '{ seg: number; ter: number; }' but required in type 'Record<Dia, number>'.

Com uma union de chaves, o Record exige todas: esquecer qua é erro.

5. Para unions e funções

type Status = "ativo" | "inativo" | "banido" | null;

type SemNulo = NonNullable<Status>;
type Bons = Exclude<SemNulo, "banido">;
type Ruins = Extract<Status, "banido" | "suspenso">;

function criar(nome: string, idade: number) {
  return { nome, idade, criadoEm: 2026 };
}
type Criado = ReturnType<typeof criar>;
type Args = Parameters<typeof criar>;

const ok1: Bons = "inativo";
const er1: Bons = "banido";
const er2: SemNulo = null;
const ok2: Ruins = "banido";
const er3: Ruins = "ativo";

const ok3: Criado = { nome: "Ana", idade: 30, criadoEm: 2026 };
const er4: Criado = { nome: "Ana" };
const ok4: Args = ["Ana", 30];
const er5: Args = ["Ana"];
$ npx tsc
src/outros.ts(14,7): error TS2322: Type '"banido"' is not assignable to type 'Bons'.
src/outros.ts(15,7): error TS2322: Type 'null' is not assignable to type 'SemNulo'.
src/outros.ts(17,7): error TS2322: Type '"ativo"' is not assignable to type '"banido"'.
src/outros.ts(20,7): error TS2739: Type '{ nome: string; }' is missing the following properties from type '{ nome: string; idade: number; criadoEm: number; }': idade, criadoEm
src/outros.ts(22,7): error TS2322: Type '[string]' is not assignable to type '[nome: string, idade: number]'.
  Source has 1 element(s) but target requires 2.

As linhas ok passaram e as er falharam, uma para cada regra: Bons não tem mais "banido"; SemNulo não aceita null; Ruins ficou só com "banido" (o "suspenso" nem existia em Status); Criado é a forma do objeto que criar devolve; e Args é a tupla dos parâmetros, [nome: string, idade: number].

Quando dá errado

Pick com um campo que não existe 
type Usuario = { id: number; nome: string };
type X = Pick<Usuario, "telefone">;
$ npx tsc
src/pick-erro.ts(2,24): error TS2344: Type '"telefone"' does not satisfy the constraint 'keyof Usuario'.

O Pick só aceita chaves de verdade do tipo. Já o Omit é mais solto e aceita qualquer texto, então um erro de digitação nele passa despercebido.

Referência rápida

UtilityResultado
Partial<T>todos os campos opcionais
Required<T>todos obrigatórios
Readonly<T>todos somente leitura
Pick<T, "a" | "b">só os campos a e b
Omit<T, "a">todos menos a
Record<K, V>objeto com chaves K e valores V
Exclude<U, X> / Extract<U, X>tira / mantém membros de uma union
NonNullable<T>tira null e undefined
ReturnType<typeof f> / Parameters<typeof f>tipo do retorno / tupla dos parâmetros

Exercícios

1. Tudo opcional

Complete:

function atualizar(mudancas: <Usuario>) { … }

2. Todos menos

Complete para criar o tipo de Usuario sem o id:

type Novo = <Usuario, "id">;

3. Chaves e valores

Complete para um objeto de nomes (texto) para notas (número):

const notas: <string, number> = {};

5. Exclude<"a" | "b" | "c", "a"> é…

Missões

Missão: faça configurar receber Partial<Config> e juntar com o padrão. Mostre o resultado de configurar({ tema: "escuro" }).

type Config = { tema: string; fonte: number; idioma: string };
const padrao: Config = { tema: "claro", fonte: 16, idioma: "pt-BR" };

function configurar(opcoes: Config): Config {
  return { ...padrao, ...opcoes };
}
console.log(configurar({ tema: "escuro" }));

type Config = { tema: string; fonte: number; idioma: string };
const padrao: Config = { tema: "claro", fonte: 16, idioma: "pt-BR" };

function configurar(opcoes: Partial<Config>): Config {
  return { ...padrao, ...opcoes };
}
console.log(configurar({ tema: "escuro" }));

{ tema: 'escuro', fonte: 16, idioma: 'pt-BR' }

Missão: crie type Fruta = "maca" | "uva" | "pera" e um estoque: Record<Fruta, number> com 5, 4 e 3. Some e mostre Total: 12 frutas.

const estoque = { maca: 5, uva: 4, pera: 3 };

type Fruta = "maca" | "uva" | "pera";
const estoque: Record<Fruta, number> = { maca: 5, uva: 4, pera: 3 };
let total = 0;
for (const qtd of Object.values(estoque)) total += qtd;
console.log(`Total: ${total} frutas`);

Total: 12 frutas

Missão: crie type Contato = Pick<Usuario, "nome" | "email"> e uma função formatar(c: Contato) que mostra Ana <ana@exemplo.com>.

type Usuario = { id: number; nome: string; email: string; senha: string };

type Usuario = { id: number; nome: string; email: string; senha: string };
type Contato = Pick<Usuario, "nome" | "email">;
function formatar(c: Contato) {
  console.log(`${c.nome} <${c.email}>`);
}
formatar({ nome: "Ana", email: "ana@exemplo.com" });

Ana <ana@exemplo.com>

Resumo

  • Utility types criam tipos a partir de outros, sem repetir campos.
  • Partial/Required/Readonly mudam todos os campos; Pick/Omit escolhem; Record monta chave → valor.
  • Exclude, Extract e NonNullable filtram unions; ReturnType e Parameters leem funções.
